# 业务逻辑与接口清单

写接口幂等、完整成功字段、槽位限制和可直接处理的错误码见：[05-幂等与错误码契约.md](./05-幂等与错误码契约.md)。

## 一、独立 H5 流程

1. 城市后台把创建二维码接口返回的 `data.registrationURL` 直接编码为二维码；用户扫码即打开独立 H5 的该地址。H5 从 URL 查询参数读取 `code`，再调用 `GET /api/v1/avatar/public/registration-context?code={shortCode}`。短码只定位城市入口，绝不携带城市运营账号、登录态或权限；无效即停止流程，优先展示服务端配置的固定 `400` 客服电话 `data.supportPhone`。
2. 用户输入姓名、手机号、性别。手机号调用 `POST /avatar/auth/sms/send`，测试响应中的 `data.mockCode` 仅可在测试页回填。
3. 调用 `POST /avatar/auth/login`，保存 `data.accessToken` 和 `data.refreshToken`；全部受保护接口携带 `Authorization: Bearer {accessToken}`。
4. 测试联调可按需调用 `POST /avatar/identity-verifications` 和 test 完成接口验证 Mock 实名链路；名单绑定不依赖该记录。生产环境不得调用 Mock 接口。
5. 调用 `POST /avatar/roster-binding/confirm`，提交二维码短码、姓名和性别；服务端以姓名、短信验证手机号、性别进行同城名单绑定。名单须已通过后台批量实名核验；H5 不传、不读取身份证号。失败时展示服务端 `message`、`data.reasonCode`、`data.action` 及 `fieldErrors`，可明确提示姓名、手机号、性别不一致，名单实名核验中/未通过，或导入行身份证号校验位错误等本人可操作原因。
6. 调用 `GET /avatar/consents/current` 后展示协议和 365 天保存规则；同意后调用 `POST /avatar/consents`。
7. 进入 H5 或恢复页面时先调用 `GET /avatar/profiles/me`：仅 `CONSENT_PENDING` 可首次创建采集会话；`COLLECTING` 直接恢复 `latestSessionId`。已提交、质检中、已归档不得再调普通创建接口，必须展示档案进度。
8. 首次采集调用 `POST /avatar/collection-sessions`，逐项获取上传凭证、直传、确认素材；必须有 8 张照片和 1 个朗读视频。用户取消或替换尚未确认的上传时，立即调用 `POST /avatar/collection-sessions/{id}/assets/cancel` 释放并发名额；不得等待凭证自然过期。体型资料使用 `PATCH /avatar/collection-sessions/{id}/body-data`。
9. 调用 `POST /avatar/collection-sessions/{id}/submit`，无请求体。随后轮询 `GET /avatar/profiles/me`，按 `data.status` 跳转处理中、人工复核、归档或补采页面。首次建档只允许提交一次。轮询响应的 `data.summary.bodyDataFilled` 必须直接作为“体型资料已填写”标记；体型资料保存成功后该字段为 `true`，`data.submittedAt` 为本次采集提交时间。
10. 仅服务端质检状态为 `RESHOOT_REQUIRED` 时，才可调用 `POST /avatar/profiles/me/reshoot` 创建新采集版本；不得由已归档用户主动重复建档。删除使用 `POST /avatar/profiles/me/deletion-requests`，状态读取 `GET /avatar/profiles/me/deletion-requests/latest`。

## 二、H5 路由清单

| 场景 | 方法与路径 | 请求关键字段 | 前端要点 |
| --- | --- | --- | --- |
| 城市入口 | `GET /avatar/public/registration-context` | `code` query | 无 token；保存返回的短码上下文。 |
| 短信 | `POST /avatar/auth/sms/send` | `mobile`, `scene=AVATAR_LOGIN` | 默认 60 秒倒计时、同手机号 10 次/自然日；两类限频均读 `data.retryAfter`；测试环境才读取 `mockCode`。 |
| 登录 | `POST /avatar/auth/login` | `mobile`, `smsCode` | 保存独立 AVATAR_H5 token。 |
| 刷新/退出 | `POST /avatar/auth/refresh`、`POST /avatar/auth/logout` | `refreshToken` / 无 | 刷新失败即清空会话。 |
| Mock 实名 | `POST /avatar/identity-verifications` | `verificationMethod=MOCK` | 仅测试环境。 |
| 完成 Mock 实名 | `POST /avatar/test/identity-verifications/{id}/complete` | `name`, `gender`, `idNumberLast4?` | 仅测试环境；不得收集完整身份证号。 |
| 名单绑定 | `POST /avatar/roster-binding/confirm` | `registrationCode`, `name`, `gender` | 后端以姓名、登录手机号、性别匹配已实名导入名单。 |
| 授权 | `GET/POST /avatar/consents/current`、`/avatar/consents` | 协议版本、`accepted=true` | 仅 `COLLECT_AND_ARCHIVE`。 |
| 采集 | `POST /avatar/collection-sessions` | 无 | 仅首次建档可创建；`COLLECTING` 返回原 sessionId 续传。已提交后返回 `409 AVATAR_COLLECTION_ALREADY_SUBMITTED`。 |
| 上传 | `POST /avatar/collection-sessions/{id}/assets/upload-credentials`、`.../confirm`、`.../cancel` | `FACE_PHOTO/FACE_01..08` 或 `VOICE_VIDEO/VOICE_VIDEO`、SHA-256、MIME、大小 / token、哈希 / `uploadToken` | 凭证字段为 `uploadURL`，直传 PUT 原始二进制；最多 3 个未确认凭证，超限读 `data.retryAfter/maxParallel`。取消、替换或上传失败时立即调 `cancel` 释放名额。 |
| 体型 | `PATCH /avatar/collection-sessions/{id}/body-data` | 调用时性别、身高、体型必填；三围可选 | 整个体型步骤可跳过；`bodyType` 当前是非空自由字符串，提交素材时后端不校验是否已填写。 |
| 提交/档案 | `POST .../submit`、`GET /avatar/profiles/me` | submit 无 body | 轮询档案状态；`summary.photoCount`、`summary.videoCount`、`summary.bodyDataFilled` 直接回显当前采集汇总，`submittedAt` 为提交时间。不得用本地缓存推断体型资料是否已保存。 |
| 补采/删除 | `POST /avatar/profiles/me/reshoot`、`POST /avatar/profiles/me/deletion-requests`、`GET .../latest` | reason 可选 | 仅 `RESHOOT_REQUIRED` 可补采，不复用旧素材。 |

## 三、后台前端接口范围

后台工作人员：名单模板/导入/错误回执/名单列表、二维码创建暂停恢复、提醒短信、城市档案进度和去标识化导出。扫码 H5 统一展示后端配置的固定 `400` 客服电话，不维护城市联系人。平台管理员：人工质检待办、素材一次性预览、审核决定、删除审批、归档包导出、一次性密码与重新生成。

后台名单的目标字段为姓名、身份证号、性别、手机号；导入前先执行后台实名 Mock，核验通过才能写入有效名单。该目标尚未在后端实现，后台前端开发应等待后端迁移和接口完成；完整身份证号永不下发至 H5。
