# 业务逻辑与接口清单

## 一、独立 H5 流程

1. 扫描城市二维码，调用 `GET /api/v1/avatar/public/registration-context?code={shortCode}`；无效即停止流程并展示 `supportPhone`。
2. 用户输入姓名、手机号、性别。手机号调用 `POST /avatar/auth/sms/send`，测试响应中的 `data.mockCode` 仅可在测试页回填。
3. 调用 `POST /avatar/auth/login`，保存 `data.accessToken` 和 `data.refreshToken`；全部受保护接口携带 `Authorization: Bearer {accessToken}`。
4. 测试环境调用 `POST /avatar/identity-verifications`，再调用 `POST /avatar/test/identity-verifications/{verificationId}/complete`，参数使用用户输入的姓名和性别。随后轮询 `GET /avatar/identity-verifications/latest`，仅 `data.status=PASSED` 可继续。
5. 调用 `POST /avatar/roster-binding/confirm`，提交二维码短码。服务端以姓名、短信验证手机号、性别进行同城名单绑定。失败不得显示哪一项不一致。
6. 调用 `GET /avatar/consents/current` 后展示协议和 365 天保存规则；同意后调用 `POST /avatar/consents`。
7. 调用 `POST /avatar/collection-sessions`，逐项获取上传凭证、直传、确认素材；必须有 8 张照片和 1 个朗读视频。体型资料使用 `PATCH /avatar/collection-sessions/{id}/body-data`。
8. 调用 `POST /avatar/collection-sessions/{id}/submit`，无请求体。随后轮询 `GET /avatar/profiles/me`，按 `data.status` 跳转处理中、人工复核、归档或补采页面。
9. 已归档用户可主动调用 `POST /avatar/profiles/me/reshoot` 开始新采集版本；删除使用 `POST /avatar/profiles/me/deletion-requests`，状态读取 `GET /avatar/profiles/me/deletion-requests/latest`。

## 二、H5 路由清单

| 场景 | 方法与路径 | 请求关键字段 | 前端要点 |
| --- | --- | --- | --- |
| 城市入口 | `GET /avatar/public/registration-context` | `code` query | 无 token；保存返回的短码上下文。 |
| 短信 | `POST /avatar/auth/sms/send` | `mobile`, `scene=AVATAR_LOGIN` | 60 秒倒计时；测试环境才读取 `mockCode`。 |
| 登录 | `POST /avatar/auth/login` | `mobile`, `smsCode` | 保存独立 AVATAR_H5 token。 |
| 刷新/退出 | `POST /avatar/auth/refresh`、`POST /avatar/auth/logout` | `refreshToken` / 无 | 刷新失败即清空会话。 |
| Mock 实名 | `POST /avatar/identity-verifications` | `verificationMethod=MOCK` | 仅测试环境。 |
| 完成 Mock 实名 | `POST /avatar/test/identity-verifications/{id}/complete` | `name`, `gender`, `idNumberLast4?` | 仅测试环境；不得收集完整身份证号。 |
| 名单绑定 | `POST /avatar/roster-binding/confirm` | `registrationCode` | 失败只展示统一提示和运营电话。 |
| 授权 | `GET/POST /avatar/consents/current`、`/avatar/consents` | 协议版本、`accepted=true` | 仅 `COLLECT_AND_ARCHIVE`。 |
| 采集 | `POST /avatar/collection-sessions` | 无 | 取得 sessionId、槽位及要求。 |
| 上传 | `POST /avatar/collection-sessions/{id}/assets/upload-credentials`、`.../confirm` | 类型、槽位、哈希、MIME、大小 / token、哈希 | 不保留永久地址。 |
| 体型 | `PATCH /avatar/collection-sessions/{id}/body-data` | 性别、身高、体型、三围可选 | 仅当前会话。 |
| 提交/档案 | `POST .../submit`、`GET /avatar/profiles/me` | submit 无 body | 轮询档案状态。 |
| 补采/删除 | `POST /avatar/profiles/me/reshoot`、`POST /avatar/profiles/me/deletion-requests`、`GET .../latest` | reason 可选 | 不复用旧素材。 |

## 三、后台前端接口范围

后台工作人员：名单模板/导入/错误回执/名单列表、城市建档联系人、二维码创建暂停恢复、提醒短信、城市档案进度和去标识化导出。平台管理员：人工质检待办、素材一次性预览、审核决定、删除审批、归档包导出、一次性密码与重新生成。

后台名单的目标字段为姓名、身份证号、性别、手机号；导入前先执行后台实名 Mock，核验通过才能写入有效名单。该目标尚未在后端实现，后台前端开发应等待后端迁移和接口完成；完整身份证号永不下发至 H5。
