# Avatar H5 幂等与错误码契约

## 写接口统一规则

以下接口必须带 `Idempotency-Key`：`/auth/sms/send`、`/auth/login`、`/auth/refresh`、`/auth/logout`、`/identity-verifications`、`/roster-binding/confirm`、`/consents`、`/collection-sessions`、上传凭证、素材确认、取消上传、体型资料、提交、补采、删除申请。

- 值为 16–128 位字母、数字、`.`、`_`、`-`；每次用户动作生成一个新值，网络重试必须复用原值与原请求体。

## 可操作错误详情

除系统内部故障外，前端必须展示服务端返回的 `message`，并按需使用 `data.reasonCode`（稳定细分原因）、`data.action`（下一步操作）和 `fieldErrors[]`（具体输入项）。名单绑定允许向本人明确展示姓名、手机号、性别不一致、名单实名核验状态以及与本人姓名和手机号关联的导入行错误；不得返回其他人员资料或完整身份证号。
- 相同主体、方法、路由、键、请求体：返回首次 `HTTP` 状态与 `data`，响应头 `Idempotency-Replayed: true`。
- 同键不同请求体：`409 IDEMPOTENCY_CONFLICT`；前端不得自动改键重试，应提示用户刷新状态后重新操作。
- 缺少键：`400 VALIDATION_REQUIRED`；格式错误：`400 VALIDATION_FORMAT_INVALID`。
- `POST /auth/logout` 的重放只允许返回已持久化的首次结果，不会恢复已撤销会话。

## 前端必须读取的成功字段

| 场景 | `data` 字段 |
| --- | --- |
| 短信 | `expiresIn`、`retryAfter`；仅测试环境可能有 `mockCode` |
| 登录/刷新 | `accessToken`、`refreshToken`、`expiresIn`、`tokenType`、`account.id`、`account.mobileMasked`、`account.clientType` |
| 当前授权 | `status`、`consentId?`、`consentType`、`agreementVersion`、`agreementContent`、`retentionDays`、`retentionUntil?` |
| 创建/恢复采集 | `sessionId`、`status`、`photoRequiredCount`、`videoRequired`、`requiredSlots[]`、`resumed` |
| 上传凭证 | `uploadToken`、`uploadURL`、`expiresIn`、`method`、`headers.Content-Type` |
| 素材确认 | `assetId`、`captureSlot`、`status` |
| 提交 | `status`、`processingTaskId`；不完整时错误 `data` 含 `photoCount`、`videoCount`、`missingSlots[]` |
| 档案 | `status`、`realNameStatus`、`collectionStatus`、`qualityStatus`、`archiveStatus`、`retentionUntil`、`latestSessionId`、`summary`、`canRequestDeletion` |

`requiredSlots` 固定为 `FACE_01` 至 `FACE_08`（`FACE_PHOTO`、仅 `image/jpeg`、每个最大 8 MiB）以及 `VOICE_VIDEO`（`VOICE_VIDEO`、`video/mp4` 或 `video/webm`、最大 60 MiB）。

## 错误码表

| HTTP | 错误码 | 前端处理 |
| --- | --- | --- |
| 400 | `VALIDATION_REQUIRED` / `VALIDATION_FORMAT_INVALID` | 高亮字段；幂等键问题重新生成键后再提交。 |
| 401 | `AUTH_TOKEN_EXPIRED` | 清理本设备会话，返回登录。 |
| 409 | `IDEMPOTENCY_CONFLICT` | 不自动重试；刷新状态并让用户重新发起。 |
| 409 | `AVATAR_PROFILE_STATE_INVALID` / `AVATAR_COLLECTION_SUBMIT_CONFLICT` | 刷新档案状态，禁止当前动作。 |
| 409 | `AVATAR_COLLECTION_ALREADY_SUBMITTED` | 首次档案已提交，跳转档案进度；不得创建或提交第二个普通采集会话。 |
| 409 | `AVATAR_RESHOOT_REQUIRED` | 当前档案只能通过补采入口继续；展示补采引导，不调用普通建会话。 |
| 409 | `AVATAR_PROFILE_DELETION_PENDING` | 展示删除处理中，禁止新采集。 |
| 412 | `AVATAR_CONSENT_REQUIRED` | 跳转授权页并展示 `agreementContent`。 |
| 422 | `AVATAR_COLLECTION_INCOMPLETE` | 用 `data.missingSlots` 定位必拍槽位。 |
| 422 | `AVATAR_UPLOAD_TOKEN_INVALID` / `AVATAR_UPLOAD_NOT_FOUND` / `AVATAR_UPLOAD_INTEGRITY_INVALID` | 重新申请凭证并重新上传该槽位。 |
| 422 | `AVATAR_QRCODE_INVALID` / `AVATAR_ROSTER_MATCH_NOT_FOUND` | 停止流程；只展示服务端统一文案和城市联系方式。 |
| 422 | `AVATAR_SMS_CODE_INVALID` | 提示重新输入或重新获取验证码。 |
| 429 | `AVATAR_SMS_RATE_LIMITED` | 用 `data.retryAfter` 秒数启动倒计时。 |
| 503 | `AVATAR_SMS_PROVIDER_NOT_CONFIGURED` / `AVATAR_SMS_UNAVAILABLE` | 提示稍后重试；生产不能显示 Mock 验证码。 |
| 503 | `AVATAR_STORAGE_UNAVAILABLE` / `AVATAR_UPLOAD_TOKEN_UNAVAILABLE` | 保留本地采集，稍后重新申请上传凭证。 |

本地 `test.yaml` 可使用后端 Mock 存储，凭证会指向本机后端的 Mock `PUT` 路由，`localhost:5273` 与 `127.0.0.1:5273` 不需要 COS CORS 配置。服务器测试如需保留后台 COS，可仅配置 `avatar.asset_storage: {provider: mock, ...}`，它只影响个人形象素材凭证，不影响后台通用文件。生产对象存储直传的跨域（CORS）仍由 COS 桶部署配置控制，不属于该 API 契约；上线前需另行在 COS 控制台以真实 H5 Origin 验收 `PUT`、`Content-Type` 与预签名 URL。

## B-03：档案与删除状态全集

| 档案 `data.status` | H5 行为 |
| --- | --- |
| `NOT_STARTED` / `CONSENT_PENDING` | 完成授权前置步骤，不可采集。 |
| `COLLECTING` | 继续当前 `latestSessionId` 采集。 |
| `AUTO_QUALITY_CHECKING` / `MANUAL_REVIEW` | 轮询档案，轮询间隔遵循本文末尾 S-04。 |
| `ARCHIVED` | 可补采或申请删除。 |
| `RESHOOT_REQUIRED` | 仅可发起补采。 |
| `REJECTED` | 质检未通过；展示统一提示并等待运营处理。 |
| `DELETION_REQUESTED` / `DELETION_PROCESSING` | 停止新采集、补采及删除重复提交；读取删除申请进度。 |
| `DELETED` | 终态，不恢复旧档案和旧素材。 |

删除申请 `status`：`NONE`、`PENDING`、`PROCESSING`、`COMPLETED`、`REJECTED`；兼容读取历史 `APPROVED`。`REJECTED` 后档案恢复为 `ARCHIVED`。重新建档必须由后台重新导入一条有效名单，再走新的绑定流程；不得复用已删除档案。

## B-04：补充错误码

| HTTP | 错误码 | 前端处理 |
| --- | --- | --- |
| 404 | `AVATAR_PROFILE_NOT_FOUND` / `AVATAR_COLLECTION_NOT_FOUND` | 回到绑定或重新创建会话，不能猜测状态。 |
| 422 | `AVATAR_REAL_NAME_REQUIRED` | 回到实名/绑定前置步骤。 |
| 422 | `AVATAR_ROSTER_ALREADY_BOUND` | 展示已建档统一文案，不泄露名单信息。 |
| 429 | `AVATAR_SMS_DAILY_LIMITED` | 以 `data.retryAfter` 秒倒计时至次日。 |
| 429 | `AVATAR_UPLOAD_CONCURRENCY_LIMITED` | 保留本地素材，等待后重试；`data.maxParallel` 为并行上限。 |
| 429 | `AVATAR_PROFILE_POLL_RATE_LIMITED` | 以 `data.retryAfter` 后再次查询。 |
| 503 | `AVATAR_RATE_LIMIT_UNAVAILABLE` | 保留本地输入并提示稍后重试。 |

未列出的 `INTERNAL_ERROR` 统一显示“服务暂不可用”，并携带 `requestId` 给客服排查。

## B-05：体型资料

体型资料在**全流程中可不填写**：不调用 `PATCH body-data` 也可提交九个必需采集槽位。若调用该接口，`gender`（`MALE`/`FEMALE`）、`heightCm`（>0 且 ≤300，cm）和非空 `bodyType` 均必填；`bustCm`、`waistCm`、`hipsCm` 均为可选、可单独填写、范围 >0 且 ≤300 cm。当前后端不限制 `bodyType` 枚举，H5 可用自身选项展示，但不能把某个固定枚举视为服务端校验规则。

## C-01 与 S-04：服务电话、限频和并发

- 无效、有效或暂停二维码均在 `data.supportPhone` 返回 `avatar.fallback_support_phone` 固定客服电话；不按城市维护联系人或电话号码。
- 短信重发间隔、日上限、上传凭证并行数和状态轮询间隔均由 `avatar` 配置控制；默认值为 60 秒、10 次/自然日、3 个未确认上传凭证、2 秒。
- 上传并行约束针对“已领凭证但未确认”的直传；凭证有效期 10 分钟，确认成功即时释放名额。用户取消、替换或上传失败时，H5 必须立即调用 `POST /avatar/collection-sessions/{id}/assets/cancel`，以 `uploadToken` 释放名额；10 分钟仅用于关闭页面、断网等异常退出兜底。本地 Mock 不依赖 COS CORS；生产 COS 桶仍须以真实 H5 Origin 验收 `PUT` 与 `Content-Type`。
