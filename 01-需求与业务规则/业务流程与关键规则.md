# v0.5 业务流程与关键规则

版本：2026-09-29  
用途：供产品、业务、前后端与测试共同确认“谁在什么条件下做什么、产出什么、哪些操作绝对禁止”。状态枚举、状态迁移和超时任务以《业务状态机与流转规则》为唯一维护来源，本文不重复维护状态表。

## 1. 使用约定

- **已实现**：当前后端已有路由、业务服务、迁移或测试覆盖的能力；实现细节以代码和接口契约为准。
- **已定案待开发**：业务规则已确认，但尚未形成完整接口/数据表/测试；不得在原型或联调中标成已完成。
- **待后续开发**：属于一期范围，按《最新待开发任务表》实施。
- 所有写操作必须遵守权限、数据范围、乐观锁/幂等键、审计留痕和敏感信息脱敏；文件业务只传 `fileId`，不得暴露长期存储地址。

## 2. 已实现业务流程

### 2.1 平台账号、组织、基础配置与创作者入驻

```text
平台管理员维护组织、账号、地区、标签和配置
→ 创作者短信注册/登录
→ 提交个人或企业主体实名认证
→ 核验通过
→ 浏览 IP 商城、创建授权订单
```

- 后台账号、组织、地区、标签和授权方案按权限与数据范围维护；城市运营只能操作本城市数据。
- 创作者账号可登录不等于可购买；购买前必须账号有效且实名认证已通过。
- 企业/工作室可留存授权委托书；它不替代实名核验，也不作为购买授权的额外人工审批。
- 敏感身份证件、手机号、授权委托书和认证资料仅按最小权限读取，下载与查看均审计。
- 平台管理员可查看全部原始敏感字段；版权/合规人员在审核职责范围内查看完整值；城市运营方仅可查看本城市、本人数据范围内的完整值；其余角色及公开接口仅返回对应 `*Masked` 脱敏字段。前端不得尝试还原脱敏值。

### 2.2 授权方案与分配方案

```text
平台维护分配方案
→ 创建授权方案草稿
→ 版权/合规审核
→ 平台启用
→ IP 确权时绑定方案与分配规则
→ 方案及分配规则锁定
```

- 授权方案规定授权方式、期限、地区、场景、内容类型、商业化/二创/N 创权限和名额，不承载 IP 实际交易价。
- IP 确权时确认建议交易价、授权方案和分配规则；订单创建时再将可交易内容完整写入订单快照。
- 已被 IP 绑定的授权方案和分配方案不得修改、停用或删除；需要改变规则必须新建方案/版本，并用于新的 IP 确权。
- 授权方案提交、审核、启用和停用时，方案主表与其当前授权方案版本必须在同一事务中同步为相同状态；商城仅展示绑定版本为 ENABLED 的 IP，主表已启用而当前版本仍为草稿属于数据不一致，不得绕过版本校验展示。
- 有限名额由服务端预占并转正式占用；不限额方案不创建预占记录；独家买断按唯一占用处理。

### 2.3 IP 入库、DCI 核验、确权与上架

```text
城市运营保存 IP 草稿
→ 上传权属证明、展示资料并选择固定授权/分配方案
→ 上传 DCI 证书，或申请 DCI 代办
→ 提交版权/合规审核
→ DCI 核验
→ 版权/合规确认权属并取得 IP 确权存证成功回执
→ 自动上架 IP 商城
```

- 一个 IP 仅有一个原始权利人和一个主归属城市；确权后主归属城市不得直接修改，纠错只能走留痕的异常处理。
- DCI 代办仅是取得 DCI 证书的协助流程，不替代 DCI 核验或版权/合规确权。现有代办处理记录可标记为已联系、处理中、已完成或已关闭，并可生成私有 DCI 代办资料包。
- DCI 证书已核验只是确权前置条件；IP 只有在权属确认和存证回执成功后才自动上架。
- 已上架 IP 可暂停、恢复或下架；暂停/下架停止新购买，不改变历史合同和已生效授权。

### 2.4 创作者商城、待支付订单与名额预占

```text
创作者查看已上架 IP
→ 查看购买预览
→ 勾选合同条款
→ 创建待支付授权订单
→ 服务端预占有限名额（30 分钟）
→ 取消或超时释放预占 / 支付成功转正式占用
```

- 创建订单必须校验创作者实名、IP 商城可见、方案启用、名额可用、同一创作者不存在该 IP 的有效授权或未过期待支付订单。
- 下单时固定买方展示资料、IP、权利说明、方案、价格、期限、范围、分配规则和合同条款；后续合同只读取订单快照，不回读可变业务表。
- 相同幂等键不重复创建订单或名额预占；支付取消、超时或状态改变均不得产生有效合同与授权。

### 2.5 测试 Mock 支付、授权生效、合同与存证补偿

```text
仅 test 环境发起 Mock 支付成功
→ 同一事务写入支付流水、订单支付结果、正式名额占用、授权范围快照和有效授权
→ 提交合同/凭证异步生成任务
→ 生成 PDF 合同及凭证
→ 自动提交合同存证
→ 成功写回回执；失败按任务重试，不回滚支付和授权
```

- Mock 仅模拟成功，生产微信支付、回调验签、查单不属于该流程。
- 支付成功后的有效授权立即可查；合同生成是后置任务，前端在“我的授权/购买记录”中查询并下载，不要求支付成功页立刻弹出文件。
- 当前合同任务的实际状态为“未生成、待生成、已生成、生成失败”；合同存证状态与合同生成状态分开保存。合同与凭证生成/存证失败不回滚支付、名额占用或授权。
- 合同只显示购买方必要信息及脱敏证件标识，不写入身份证号、统一社会信用代码、手机号或银行账户原文。
- 合同存证成功须有回执/交易 Hash；失败时记录失败原因、重试次数和下一次重试时间。

### 2.6 文件、内容检测、审计与存证基础

```text
上传私有文件
→ 文件服务校验类型与大小、计算 Hash
→ 业务对象绑定 fileId
→ 按对象、角色、数据范围和业务状态校验
→ 签发短期下载链接并记录下载日志
```

- 文字内容在提交业务前调用内容检测；检测不通过或外部服务异常均不得绕过进入后续流程。
- 存证适配器和回调已具备 Mock 基础；没有真实回执不得标记为存证成功。
- 关键写操作、状态变化、代办资料包生成、文件读取/下载和存证回调都应审计；错误响应应返回具体资源/字段定位信息，而非笼统“资源不存在”。

### 2.7 IP 入库素材包、DCI 申报包锁定与冻结（`API-IP-04-R`）

```text
IP 草稿 → 上传完整素材包与权属证明 → 生成素材包清单 Hash
→ 锁定 DCI 申报包或独立回填 DCI 证书 → DCI 核验
→ 版权/合规确认权属与素材包存证 → IP 确权、素材包 FROZEN、IP 上架
→ 创作者购买授权后按范围下载素材
```

- 素材包固化文件 ID、文件 SHA-256、角色、排序、可交付标识与适用授权范围，并据此生成清单 Hash；链上只存 Hash/回执，不上传素材二进制文件。
- DCI 代办申请锁定当次申报包；补正须终止或退回原请求、重新生成 Hash 并创建新请求。DCI 证书独立回填，不得改写锁定的原 IP／素材包。
- 只有 DCI 核验、权属确认和关键材料/素材包存证均成功，素材包才可 `FROZEN`；冻结后不可覆盖、替换、追加或删除。

### 2.8 创作者已购授权的素材包查询与下载（`API-AUT-04-R`）

```text
创作者查询本人有效授权 → 查询已冻结且已存证的素材包和可交付素材项
→ 校验授权范围与用途 → 签发短期下载链接 → 记录下载日志
```

- 仅购买方本人、授权有效、素材包已冻结且存证成功、素材项允许交付时可下载；授权到期或解除后停止签发新的下载链接。
- 合同、授权凭证和授权范围快照引用素材包清单 Hash，历史合同、凭证及下载日志持续保留。

### 2.9 二创作品提交、两级审核与确权（`API-CNT-01`）

```text
有效且允许二创的授权 + 已冻结已存证素材包
→ 提交作品、素材引用、五项声明与独创表达说明 → 文本检测
→ 版权初审 → 合规复核 → 确权快照与 Mock 存证 → RIGHTS_CONFIRMED
```

- 原始 IP 权属永不转移；创作者只就平台确认的新增独创表达主张权利。新增表达比例须不低于 51%，这是平台内部准入标准，不是法定版权比例。
- 检测拦截、检测异常、退回或驳回均不得绕过流程；作品确权后不可覆盖修改，后续创作应新建作品。

### 2.10 商品/SKU、二级审核与上下架（`API-CNT-02`）

```text
有效商业授权 + 一件 RIGHTS_CONFIRMED 作品 → 提交商品、SKU、售后及文件
→ 自动校验 → 版权初审 → 合规复核 → PUBLISHED
→ 下架 → 新版本重提并重新走校验与两级审核
```

- SKU 由服务端生成：`SKU-{IP资产编号}-{关联作品编号}-{商品编号末6位}-{两位顺序号}`；前端不提交 `skuCode`。售价必须大于 0，库存可为 0。
- 封面和公开版权说明必填；品牌、生产方、条码、税率，以及商品视频、说明书、质检报告、生产许可证等附件可选。
- 检测拦截或异常不进入人工审核，创作者修改后重提；退回、驳回、检测失败可覆盖当前未发布版本。已发布商品必须先下架，下架后重提创建新版本，历史版本和后续订单快照不被覆盖。

## 3. 已定案待开发业务流程

### 3.1 后续活动、消费者交易、履约、售后与结算

| 业务 | 主流程 | 关键规则 |
| --- | --- | --- |
| 文旅活动 | 有效授权 → 活动/场次/票种校验 → 自动发布 → 预约/核销 | 有成功报名不得下架或改期，只能暂停报名 |
| 消费者订单 | 下单预占 → 支付 → 发货/核销 → 完成 | 不超卖；回调幂等；付款不能伪造成功 |
| 售后退款 | 申请 → 审核 → 退货/退款 → 库存或名额恢复 → 分账冲销 | 退款未成功不得标记售后完成 |
| 分账结算 | 订单完成/核销 → 计算 → 风险冻结或冲销 → 财务复核 → 线下付款 | 售后、风险或异议期间不得结算；独家买断不产生后续二传分账 |

以上业务尚未形成完整模块，具体开发顺序、接口和验收以《最新待开发任务表》及《API功能清单与开发任务拆分》为准。

## 4. 跨业务不可突破规则

1. 已支付不等于合同已生成；合同/存证失败不得回滚已确认的支付与有效授权，但必须可查询、可重试、可审计。
2. 订单、合同、凭证、授权范围和未来素材交付均以各自固化快照/Hash 为准；禁止用修改后的业务资料覆写历史交易事实。
3. 所有外部回调、支付、下载、存证和定时补偿均须可幂等重放，且不能重复扣名额、重复生成合同、重复结算或重复核销。
4. 未经权限、数据范围、业务状态和文件用途四重校验，不得签发文件下载链接。
5. 真实服务尚未接入时，只能明确标识 Mock/测试能力；不得将模拟支付或模拟存证表述为生产能力。
