版本：v0.4  
状态：测试与上线验收基线

## 1. 测试目标与边界

### 1.1 测试目标

验证一期 MVP 能稳定完成以下主业务闭环，并确保权限、资金、版权、存证与个人信息不因异常操作而失控：

```text
城市运营录入 IP
→ 版权/合规确权并绑定固定方案
→ 平台管理员上架 IP
→ 创作者注册、实名、购买授权、微信支付
→ 生成合同/凭证/范围快照
→ 创作者提交作品并确权
→ 创建商品或活动并自动校验发布
→ 消费者浏览、下单/预约、微信支付
→ 发货签收或现场核销
→ 售后退款（适用时）
→ 自动分账、线下结算、真实存证与审计留痕
```

### 1.2 一期不测范围

以下能力不属于一期验收对象，出现相关页面或接口应视为范围蔓延：数字人民币、自动续期、授权成功后的取消退款、发票、优惠券/会员/复杂营销、活动改期、提货自取、商品草稿、多账号、投诉工单、活动人工发布审核。商品实行已确认的版权初审与合规复核。

### 1.3 通过标准

1. 全部 P0 用例通过，无 P0/P1 级未关闭缺陷；
2. 所有写接口具备权限、状态、幂等和审计验证；
3. OpenAPI 契约与实际接口字段、枚举、错误码一致；
4. 关键对象有完整状态历史；关键材料、合同、作品等真实存证成功且有服务商回执；
5. 前端关键页面在后台与消费者 H5 均完成对应操作、状态展示与错误提示；
6. 允许保留 P2/P3 缺陷，但必须有影响说明、临时规避方式和修复排期。

### 2.3 通用检查点

每条写操作至少检查：响应 `code/requestId`、数据库主对象与状态历史、审计日志、前端状态提示、重复提交结果、越权结果和失败后的数据回滚/补偿。

## 3. 缺陷分级与提单要求

| 级别 | 定义 | 上线要求 |
| --- | --- | --- |
| P0 | 资金错误、越权泄露、合同/授权错误、存证伪成功、无法完成主链路、数据损坏 | 必须修复并回归 |
| P1 | 核心流程受阻、状态错误、关键字段错乱、重要角色不可用 | 必须修复并回归 |
| P2 | 有替代操作的功能缺陷、显示/筛选错误、非关键提示不准确 | 可带修复计划上线 |
| P3 | 体验优化、文案、非关键视觉问题 | 记录后迭代 |

缺陷单应包含：环境、账号角色、前置数据、操作步骤、预期/实际结果、请求 `requestId`、截图或录屏、相关订单/IP/授权编号与日志时间。

| --- | --- | --- | --- |

## 5. P0 非功能与异常验收

| 编号 | 场景 | 预期结果 | 优先级 |
| --- | --- | --- | --- |
| NFR-001 | 订单支付、库存/名额预占、退款、核销并发提交 | 不超卖、不重复扣减、不重复退款/分账；重复请求稳定返回 | P0 |
| NFR-002 | 微信支付/物流/存证回调重复、乱序或验签错误 | 验签失败不改变业务状态；合法重复回调幂等；乱序不回退终态 | P0 |
| NFR-003 | 短信、实名、敏感检测、电子签章、存证服务超时 | 有明确失败/阻断状态、重试记录和可追踪请求号；商品/活动不得绕过发布 | P0 |
| NFR-004 | 刷新令牌、下载短链、私有文件越权访问 | 过期/越权全部拒绝；不暴露存储键、证件完整信息或收货地址原文 | P0 |
| NFR-005 | 关键写接口缺失/重复 `Idempotency-Key` 与旧 `If-Match-Version` | 缺失按接口规范拒绝；重复键冲突可识别；旧版本返回 `VERSION_CONFLICT` | P0 |
| NFR-006 | 服务重启后执行超时关闭、授权到期、活动过期、自动完成、存证补偿任务 | 任务可重入；不重复释放、不重复状态流转、不重复分账 | P0 |

## 6. 前后端联调验收清单

1. 前端请求、响应字段、枚举与 `OpenAPI_v0.4.yaml` 一致；金额均以字符串处理，ID 不转数字。
2. 所有写操作传递 `Idempotency-Key`；状态编辑传递版本号或 `If-Match-Version`。
3. 前端只使用后端返回的 `availableActions` 决定操作入口，不自行推导状态。
4. 下拉、单选、复选选项来自字典或接口，不写死中文状态文字。
5. 统一处理 `AUTH_`、`VALIDATION_`、`VERSION_`、状态冲突、库存/名额不足和内容检测失败提示。
6. 文件上传只保存 `fileId`；下载使用短期地址，不展示存储键或私有链接。
7. H5 公开页面不得展示版权边界细节、权利证明、合同、实名、内部分账、审核意见或链服务技术信息。
8. 页面应展示处理中的异步状态；禁止在检测/存证未回执时显示“已发布”或“已存证”。

## 7. 回归执行顺序与验收证据

### 7.1 每次发版最小回归

```text
AUTH-001 → IP-001 → IP-003 → IP-004 → IP-005 → AUT-003 → AUT-006
→ CNT-002 → CNT-004 → ORD-002 → ORD-004 → FIN-001 → FIN-005 → OPS-001
```

商品售后分支：`ORD-008 → FIN-002`。活动分支：`CNT-007 → ORD-005 → ORD-007 → FIN-001`。

### 7.2 上线验收包

上线前应归档以下材料：

1. 用例执行记录、通过率和缺陷清单；
2. P0 主链路的录屏或关键步骤截图；
3. 接口测试报告、关键并发/幂等测试结果及 `requestId`；
4. 数据库关键对象、状态历史、审计、分账、退款和存证回执抽样对账表；
5. 外部服务成功、失败、重复回调和补偿重试证据；
6. OpenAPI 版本号、前端构建版本、后端构建版本和数据库迁移版本。
