# AVATAR_H5 前后端联调确认结论与前端改动清单

> 基线：2026-10-28。以 `G:\Go\xingyanshu-backend\internal\modules\avatar` 实际路由、真实 MySQL + Redis HTTP 回归和同目录 `Avatar_H5_OpenAPI_v1.yaml` 为准。

## 一、联调结论

- H5 是独立 `AVATAR_H5`，不复用消费者端账户、会话或接口。
- 名单在后台导入时完成测试实名核验。H5 在生产环境不调用 Mock 实名接口；绑定时提交 `registrationCode`、`name`、`gender`，后端叠加已短信验证手机号完成三要素匹配。
- 所有写接口已接入 MySQL 持久化幂等。每次用户动作生成一个 `Idempotency-Key`；网络重试复用该键及原始请求体；重放返回首次 HTTP 状态和 `data`，响应头为 `Idempotency-Replayed: true`；不同请求体同键返回 `409 IDEMPOTENCY_CONFLICT`。
- 真实 MySQL + Redis HTTP 回归覆盖短信、登录/刷新、签署、建会话、体型资料、补采、九槽位上传确认、提交、删除和退出。COS 直传 CORS 仍须在部署配置后用真实浏览器验收。

## 二、前端必须按此改动

| 编号 | 当前后端契约 | 前端动作 |
| --- | --- | --- |
| B-01 | 成功外层 `code` 固定为字符串 `OK`；业务字段只在 `data` 内。 | 仅 `code === "OK"` 视为成功；错误按稳定 `code` 分支，不能解析中文文案。 |
| B-02 | 写接口要求 16–128 位 `Idempotency-Key`。 | 按一次用户动作生成键；重试保留键和请求体；见到 `Idempotency-Replayed: true` 直接消费首次结果；`IDEMPOTENCY_CONFLICT` 不自动换键重试。 |
| B-03 | 当前授权返回 `status`、`consentType`、`agreementVersion`、`agreementContent`、`retentionDays`，有效授权另有 `consentId`、`retentionUntil`。 | 直接展示服务端 `agreementContent` 与 365 天规则，提交必须 `accepted:true`。 |
| B-04 | 创建/恢复采集返回 `requiredSlots`、`photoRequiredCount=8`、`videoRequired=true`、`resumed`。 | 不维护另一套槽位字典；按响应的九个槽位和顺序渲染。 |
| B-05 | 照片为 `FACE_01..FACE_08` + `FACE_PHOTO`，仅 `image/jpeg`，最大 8 MiB；朗读视频为 `VOICE_VIDEO`，仅 `video/mp4`/`video/webm`，最大 60 MiB。 | 上传前做同样的 MIME、大小提示；仍以服务端拒绝结果为最终准则。 |
| B-06 | 上传凭证返回 `uploadToken/uploadURL/expiresIn=600/method=PUT/headers`；确认接口只提交 `uploadToken/contentHash`；取消接口为 `POST /collection-sessions/{id}/assets/cancel`，仅提交 `uploadToken`。 | 对 `uploadURL` 直传原始二进制，使用 `headers.Content-Type`；不附业务 Authorization；取消、替换或上传失败时立即调用 `cancel` 释放并发名额，凭证失效或完整性失败时重新申请。 |

| B-08 | 城市暂停时入口返回 `200`，`data.entryStatus=PAUSED`、`available=false`、`notice`；二维码无效为 `422 AVATAR_QRCODE_INVALID`，错误 `data.supportPhone` 返回统一客服电话。 | 暂停页展示服务端 `supportPhone`；无效二维码优先读错误中的 `supportPhone`，为空才使用构建期兜底，均阻止继续登录。 |
| B-09 | 短信限频为 `429 AVATAR_SMS_RATE_LIMITED` 或 `AVATAR_SMS_DAILY_LIMITED`，`data.retryAfter` 为秒。 | 按服务端秒数倒计时；生产不显示 `mockCode`。 |
| B-10 | 档案响应含 `profileId/profileNo/version/status`、实名/采集/质检/归档状态、`latestSessionId`、`summary`、`retentionUntil`、`canRequestDeletion`；查询最短间隔默认 2 秒，超过返回 `429 AVATAR_PROFILE_POLL_RATE_LIMITED`。 | 状态页按服务端 `status` 渲染并读 `retryAfter` 退避；未知状态显示“状态更新中”。 |
| B-11 | 补采仅允许 `ARCHIVED` 或 `RESHOOT_REQUIRED`；删除申请仅允许 `ARCHIVED`，进行中的删除会阻止新采集。 | 补采、删除按钮以当前档案状态和错误码二次保护；不得复用旧素材。 |

## 三、状态与错误处理

- 档案 `status`：`NOT_STARTED`、`CONSENT_PENDING`、`COLLECTING`、`AUTO_QUALITY_CHECKING`、`MANUAL_REVIEW`、`ARCHIVED`、`RESHOOT_REQUIRED`、`REJECTED`、`DELETION_REQUESTED`、`DELETION_PROCESSING`、`DELETED`。
- 删除申请 `status`：`NONE`、`PENDING`、`APPROVED`、`PROCESSING`、`COMPLETED`、`REJECTED`。
- 体型步骤可跳过；若填写则 `gender/heightCm/bodyType` 必填，三围可各自留空，`bodyType` 暂无服务端枚举。
- 删除完成后的 `DELETED` 为终态；用户若要再次建档，后台需重新导入有效名单，H5 不能恢复或复用旧档案。
- 重点错误：`AVATAR_CONSENT_REQUIRED` 回授权页；`AVATAR_PROFILE_DELETION_PENDING` 停止采集；`AVATAR_UPLOAD_TOKEN_INVALID`、`AVATAR_UPLOAD_NOT_FOUND`、`AVATAR_UPLOAD_INTEGRITY_INVALID` 重新申请并上传该槽位；`AUTH_TOKEN_EXPIRED` 清空当前设备会话；`AVATAR_STORAGE_UNAVAILABLE` 保留本地采集，稍后再试。
- `realNameStatus=ERROR` 不代表用户输入错误；显示“实名核验暂未完成，请稍后查看处理进度或联系客服”，不自动重复提交采集。

完整响应模型见 `Avatar_H5_OpenAPI_v1.yaml`，错误码表见 `05-幂等与错误码契约.md`；两者是唯一接口源，本说明不再独立维护字段副本。
