## 已实现可联调边界

- 城市长期通用二维码入口、独立短信登录、刷新、退出；
- 测试环境 Mock 短信、Mock 实名和姓名、登录手机号、性别三项名单绑定；
- 采集授权、采集会话、受控上传确认、提交；提交后由一条后台自动质检任务依次执行质检和（已配置时）正面照与名单身份的一致性核验；
- 本人删除申请；生产环境不会以 Mock 实名、质检或短信伪造成功。名单绑定使用 H5 提交的姓名、性别和已短信验证手机号匹配已完成后台 Mock 实名核验的导入名单，不依赖 H5 实名服务。

## 前端必须遵守

- 以接口契约的“已实现”标记为准；原型演示不等于接口已经上线。
- 匹配失败只展示统一提示和运营方联系电话，不能提示是哪一项不一致。
- 不显示实名原始结果、名单原始数据、存储键、长期素材地址或原始归档包。
- 只收集“采集与入库”授权；对外使用授权是后续独立任务。
- 保存期统一为首次归档起 365 天，页面须展示该规则。
- 城市运营后台创建二维码时会返回完整 `registrationURL`；该 URL 直接编码为二维码，扫码打开本独立 H5。URL 中短码只用于解析公开城市上下文，绝不携带城市账号、登录态或权限；H5 绝不读取名单、错误回执、短信通知或城市档案进度接口。
- 平台人工质检已由后台受控完成；H5 只接收本人档案的最终状态与补采原因，不能调用审核待办、素材预览令牌或审核决定接口。
- 正面照一致性核验仅在所有素材上传并确认、用户提交采集之后由后端发起。H5 不传姓名或身份证号给腾讯云，也不直接调用腾讯云；进度只读取 `GET /avatar/profiles/me` 的 `realNameStatus`。
- H5 已支持当前采集会话的加密体型资料保存、随时主动补采及最新删除申请进度；补采必须使用服务端返回的新会话，不得复制或复用旧素材。

## 后端待同步项

- 后台名单导入已使用“姓名、身份证号、手机号、性别”四列模板；导入后由后台手动执行待核验名单的实名核验。H5 仍只提交姓名、性别和登录手机号进行绑定，不采集、不展示完整身份证号。
- 写接口已实现服务端 `Idempotency-Key` 持久化去重；前端为每次用户动作生成新键，网络重试复用键和请求体；重放响应含 `Idempotency-Replayed: true`，同键不同请求体为 `409 IDEMPOTENCY_CONFLICT`。
- 所有成功响应的外层 `code` 固定为字符串 `OK`，不是 `0` 或 `200`；详细字段、状态和错误码以 `Avatar_H5_OpenAPI_v1.yaml` 和 `05-幂等与错误码契约.md` 为准。
- 原始归档包已由后台 worker 生成 AES-256 加密 ZIP；该能力不属于 H5，不得在 H5 展示原始素材或解压密码。
- 配置了腾讯云人脸核身后，`realNameStatus` 在提交时变为 `PENDING`，完成后为 `PASSED`、`REJECTED` 或 `ERROR`；未配置该能力的环境不创建该异步任务，保留名单导入时的实名状态。

## 后台前端范围

本包只交付独立 H5。城市名单导入、二维码管理、进度列表、人工质检、删除审批和导出属于后台前端；请交由同级 `08-个人数字形象IP库后台前端开发包` 实施，不能混入 H5。
