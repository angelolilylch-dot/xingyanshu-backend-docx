# 链上存证与证书前端联调边界

状态：后端至信链 Provider 与创作者端受权证书查询接口已实现。

## 1. 前端不可调用的厂商接口

至信链 `POST /api/v1/ev/save`、`GET /api/v1/ev/query`、`POST /api/v1/ev/cert`、`GET /api/v1/ev/cert` 均是后端到厂商的调用。前端不得直连、不得保存或构造 `Secret-Id`、`Signature`、私钥、`evId`，也不得轮询厂商 `certUrl`。

## 2. 创作者端查询接口

`GET /api/v1/creator/evidences/{evidenceId}/certificate`

- 必须携带创作者 JWT；仅能读取当前创作者本人 `AUTH_CONTRACT` 或 `DERIVATIVE_WORK` 的存证记录。
- 不存在和无权访问均返回 `404 RESOURCE_NOT_FOUND`；`evidenceId` 非正整数返回 `400 VALIDATION_FORMAT_INVALID`。
- 成功响应返回 `evidenceId`、`objectType`、`objectId`、`evidenceType`、`evidenceStatus`、`receiptNo`、`transactionHash`、`blockHeight`，以及 `certificate` 对象。
- `certificate` 包含 `status`、`provider`、`providerStatus`、`certUrl`、`reasonCode`。只有 `status=READY` 时 `certUrl` 才可使用；`PENDING_REQUEST`、`PENDING`、`FAILED` 都不得展示“查看链上证书”按钮。

## 3. 当前前端可做和不可做的事

- 可继续按既有业务详情返回的 `evidenceStatus`、`evidenceReceiptNo`、`evidenceTransactionHash` 展示业务存证结果；这些字段不等同于链上证书。
- 可在授权详情、二创作品确权详情中使用业务已返回的 `evidenceId` 调用本系统受权查询接口；`certificate.status=READY` 且 `certUrl` 非空时才显示“查看链上证书”。
- 不可将厂商 `/api/v1/ev/cert` 配到前端请求层，不可自行拼装厂商 URL、`evId` 或重试请求。
- 不可把 `auth_certificate`（平台生成的授权凭证 PDF）误当作至信链证书。

## 4. 展示与轮询规则

前端从受权查询接口读取如下归一化字段：

| 字段 | 规则 | 前端行为 |
| --- | --- | --- |
| `certificate.status` | `PENDING_REQUEST`、`PENDING`、`READY`、`FAILED` | 展示状态；`PENDING*` 显示“证书生成中”，`FAILED` 显示 `certificate.reasonCode` 对应的脱敏提示 |
| `certificate.certUrl` | 仅对象归属校验通过且 `certificate.status=READY` 时返回非空 | 非空时显示“查看链上证书”并在新窗口打开；空值时不渲染按钮 |
| `certificate.providerStatus` | 厂商原始状态 | 可用于排障，不作为前端状态机分支 |

该接口仅覆盖创作者本人授权合同与二创作品，不提供游客匿名查询，也不暴露私钥、签名、厂商认证头或证书任务内部重试信息。前端可在业务详情打开时请求一次；处理中按页面既有刷新机制再次请求，禁止高频轮询厂商接口。
