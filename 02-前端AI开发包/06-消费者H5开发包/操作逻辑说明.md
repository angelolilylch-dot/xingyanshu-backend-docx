# 消费者 H5 操作逻辑说明

## 活动预约（API-H5-03，已可联调）

- 进入活动详情先调用预约预览；预览不锁定名额，创建时以后端二次校验为准。
- 单次数量为 1–4；同一消费者可对同一场次多次成功预约。
- 免费票创建成功直接进入“待核销”；收费票先进入“待支付”，支付成功后才进入“待核销”。到场后由消费者扫描活动现场固定二维码，而不是向工作人员出示个人核销码。
- 待支付预约可取消；支付失败保持待支付，可重试、取消或等待 30 分钟超时。活动结束未核销自动过期，不展示退款入口。

## 到场扫码自助核销（API-FUL-02，已可联调）

1. 现场二维码携带消费者 H5 地址和 `code`。进入后先调用 `GET /api/v1/public/activity-checkin-qrcodes/{code}`，只显示活动与地点；未登录则保存完整回跳地址，登录后继续。
2. 登录后调用 `GET /api/v1/consumer/activity-check-ins/{code}/preview`。只展示当前用户可核销的本活动预约；若多笔预约，由用户明确选择一笔。
3. 确认页展示活动、场次、票种、数量、地点、核销时间窗。可申请定位并在授权时上报 `longitude/latitude/accuracy/capturedAt`，拒绝授权不阻断。
4. 用户点击“确认核销”后，以新的 `Idempotency-Key` 调用 `POST /api/v1/consumer/activity-check-ins/{code}/confirm`，请求体至少包含 `activityBookingId`。成功后刷新预约为 `VERIFIED`；同键重试视为成功重放。
5. 时间窗为场次开始前 2 小时到场次结束前。`ACTIVITY_CHECKIN_NO_ELIGIBLE_BOOKING`、`ACTIVITY_CHECKIN_NOT_OPEN`、`ACTIVITY_CHECKIN_QRCODE_INVALID` 直接展示后端 message，不猜测或展示他人预约。

## 1. 游客浏览

```text
打开首页
→ GET /public/home
→ 点击商品/活动
→ GET 对应公开详情
→ 未登录时允许继续浏览
→ 点击结算、订单、地址簿时转到登录页
```

- 首页各取最新 6 个商品和活动；地区仅影响展示筛选，不限制购买或预约地区。
- 商品/活动的公开内容只显示面向消费者的内容。公开详情不存在或已下架时显示“内容已不可用”并返回列表。
- 活动 `bookingPaused=true` 时正常展示，但预约主按钮置灰并标注“报名暂停”。

## 2. 登录与会话

```text
输入手机号 → POST /consumer/auth/sms/send
→ 输入验证码、勾选协议、提交协议版本
→ POST /consumer/auth/login
→ 保存 accessToken/refreshToken
→ GET /consumer/me → 返回来源页
```

- 登录会自动注册消费者账户；协议未勾选不得发起登录。首次及后续每一次成功登录，服务端均记录本次同意的协议版本和同意时间。
- 同一手机号允许多设备会话并存；退出仅撤销当前设备会话。前端不得提供“退出全部设备”或把当前设备退出描述为全端下线。
- 短信目前仅接测试环境 Mock。发送成功后前端开始 60 秒重发倒计时；测试返回的 `mockCode` 仅用于测试联调，生产页面不得显示或保存。
- 受保护请求首次 `401` 时只允许一个 `POST /consumer/auth/refresh`；刷新成功后原子替换双 Token 并重放等待请求；失败则清除本地会话并跳转登录页。
- 退出调用 `POST /consumer/auth/logout` 后清除本地 Token 与个人敏感页面缓存；本地购物车不因退出而删除。

## 3. 购物车、地址簿与订单（API-H5-02 完成后的既定逻辑）

```text
商品详情选择 SKU/数量 → 写入浏览器本地购物车（不锁库存）
→ 勾选一个或多个 SKU → 选择/新增收货地址
→ POST /consumer/product-orders/preview
→ 后端复核商品状态、库存、价格、运费、规则
→ 勾选规则 → POST /consumer/product-orders（幂等键）
→ 创建 PENDING_PAYMENT 订单并预占库存 30 分钟
→ 支付成功：PENDING_SHIPMENT；支付失败：仍可重试/取消；超时：PAYMENT_TIMEOUT
```

- 订单可包含不同创作者、不同商品和多个 SKU；平台统一履约与发货，不按创作者拆订单。
- 金额由后端计算：商品小计之和 + 运费；运费只支持 `FREE`、`FIXED`，均在订单中固化快照。
- 仅 `PENDING_PAYMENT` 允许取消；取消立即释放库存预占。创建、支付、取消都必须防重。
- 下单时保存商品、SKU、价格、运费、售后规则和完整收货地址快照；消费者本人查看订单时读取完整地址。

## 4. 支付与订单后续

- Mock 支付仅测试环境可见，必须同时覆盖支付成功与支付失败；生产环境没有 Mock 入口。
- 首次支付成功后订单进入 `PENDING_SHIPMENT`，预占库存转为正式消耗；重复支付结果不得改变已成功订单。
- 当前平台一笔订单一个发货单；包裹拆分为后续能力。消费者订单在 `SHIPPED`、`SIGNED` 时可查看物流，调用 `GET /consumer/product-orders/{orderId}/logistics`；前端不得直连第三方物流服务。
- 仅 `SIGNED` 且无进行中售后显示“确认收货”，调用 `POST /consumer/product-orders/{orderId}/confirm-receipt` 并携带 `Idempotency-Key`；收到 `ORDER_NOT_CONFIRMABLE` 时刷新订单。签收满 7 天且无售后由系统自动完成。售后入口仍等待 API-AFS-01。
