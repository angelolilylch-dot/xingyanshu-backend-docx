> **主版本文件：** `功能结构图/v0.4/前端修改说明.md`。前端开发包内保存同内容副本，发给前端时优先发送前端开发包中的本文件及其引用文件。

## 2026-09-07：A09 组织管理与动态菜单授权

### 影响范围

- **新增页面：** A09「组织管理」，路径建议为 `/platform/organizations`，仅平台管理员可进入。
- **调整页面：** A03「后台账号管理」、后台登录后的导航初始化。
- **后续接口：** `GET/POST /admin/orgs`、`GET/PATCH /admin/orgs/{orgId}`、`PATCH /admin/orgs/{orgId}/status`、`GET /admin/orgs/options`；菜单仍使用 `GET /auth/me`。

### 前端实现要求

1. A03 新增和编辑账号时，先调用 `GET /admin/orgs/options`，使用返回的 `id` 作为 `orgId`；不可让用户手工输入组织 ID。城市运营仅显示或仅允许选择 `orgType=CITY` 的组织。
2. A09 以组织编码、名称、类型、上级组织、城市编码、状态、版本、更新时间展示和维护组织。城市组织必须选择上级组织与城市编码；编辑和状态操作带 `If-Match-Version`。
3. 后台登录完成及刷新页面时调用 `/auth/me`，仅按 `data.menus[]` 中的 `resourceCode` 显示前端固定路由配置中的菜单；不可按角色名称直接写死菜单。`data.permissions[]` 仅控制按钮可见性，后端仍是最终权限判断。
4. 组织接口和菜单权限初始化已完成，可按最新 OpenAPI 直接联调。A03 组织下拉使用 `/admin/orgs/options` 的 `data.items[]`；A09 编辑和状态操作必须传入组织当前 `version` 作为 `If-Match-Version`。组织有启用账号或启用下级组织时，停用会返回 `409 RESOURCE_CONFLICT`。

## 2026-09-04：IP 录入字段、评估报告与接口绑定补齐

### 影响范围

- **页面：** B02「IP 新建 / 编辑 / 补充材料」、B03「IP 详情与合规审核」。
- **原型：** 管理后台原型的「IP 新建 / 编辑 / 补充材料」字段与动作。
- **接口：** `POST /ips`、`PATCH /ips/{ipId}`、`POST /ips/{ipId}/evaluation-reports`、`GET /ips`。

### B02 页面字段调整

IP 录入表单按以下分组实现，均应与 `IpCreateRequest` 字段双向绑定。

| 分组 | 前端字段 | 接口字段 | 控件 / 规则 |
| --- | --- | --- | --- |
| 基本信息 | IP 名称、IP 类型、资源来源、主归属城市、一句话简介、完整介绍、文化背景和故事、IP 特色 | `ipName`、`ipType`、`sourceType`、`mainCityOrgId`、`shortIntro`、`detailContent`、`cultureStory`、`ipFeature` | 文本均需敏感内容检测；`shortIntro` 不再使用旧字段 `mallIntro` |
| 商城展示 | 封面图、详情图、可创作方向、适用商品类型、适用文旅活动类型 | `coverFileId`、`detailFileIds`、`creativeDirections`、`applicableProductTypes`、`applicableActivityTypes` | 可创作方向为可增删的文本项；商品类型、活动类型为复选项，至少选择一项 |
| 标签 | 地域、文化、品类、商业化标签 | `regionTagCodes`、`cultureTagCodes`、`categoryTagCodes`、`commercializationTagCodes` | 可搜索多选标签；从标签接口获取受控选项，提交标签编码数组 |
| 面向创作者说明 | 公开版权说明、购买须知 | `publicCopyrightNotice`、`purchaseNotice` | 多行文本；消费者 H5 不展示权属材料，仅展示通俗版权说明 |
| 原始权利人 | 类型、名称、权利取得方式、权属说明 | `rightHolder.holderType`、`rightHolder.holderName`、`rightHolder.acquisitionMethod`、`rightHolder.rightsDescription` | 一个 IP 只允许一个原始权利人；取得方式使用固定选项 |
| 版权证明 | 证明类型、证明编号、有效起止日、证明文件 | `rightDocuments[].documentType`、`documentNo`、`validFrom`、`validTo`、`fileId` | 支持多份证明；至少一份；不再只提交旧字段 `rightDocumentFileIds` |
| DCI 证书 | 证书编号、证书文件、证书状态 | `dciCertificateNo`、`dciCertificateFileId`、`dciCertificateStatus` | 与 DCI 代办复选框互斥；选择代办时禁用并清空本组字段；未取得证书不能提交审核 |
| 评估报告 | 报告编号、评估机构、评估日期、有效期、报告文件 | `reportNo`、`institutionName`、`reportDate`、`validTo`、`fileId` | **非必填**；创建 IP 成功取得 `ipId` 后，可调用评估报告接口上传 |
| DCI 代办 | 复选框、联系人、联系电话、方便联系时间、补充说明 | `dciAssistanceRequested`、`dciAssistanceRequest.contactName`、`dciAssistanceRequest.contactMobile`、`dciAssistanceRequest.preferredContactTime`、`dciAssistanceRequest.requestNote` | 勾选后展开；联系人和联系电话必填；与 DCI 证书互斥。点击“保存 IP”时随 `POST /ips` 同一事务创建代办申请；手机号按后端返回值脱敏展示 |
| 方案与提交 | 授权方案、分配方案、提交说明 | `authPlanVersionId`、`distributionPlanId`、`submitComment` | 仅可选启用方案；提交动作携带幂等键和版本号 |

### 评估报告流程调整

1. 城市运营先保存或创建 IP，获得 `ipId`。
2. 评估报告存在时，前端可调用 `POST /ips/{ipId}/evaluation-reports` 上传；无报告可跳过，不阻断保存或提交。
3. 城市运营仅可为本人城市、且状态为 `DRAFT` 或 `SUPPLEMENT_REQUIRED` 的 IP 上传。
4. 版权/合规人员可在后续审核阶段新增或补传评估报告。

### 前端接口和数据源调整

| 用途 | 接口 / 数据源 | 前端要求 |
| --- | --- | --- |
| 创建或编辑 IP | `POST /ips`、`PATCH /ips/{ipId}` | 使用更新后的 `IpCreateRequest`；不得继续发送 `mallIntro`、`rightDocumentFileIds` |
| 查询 IP | `GET /ips?keyword={可选}&pageNo=1&pageSize=20` | `keyword` 仅模糊匹配 IP 编号和 IP 名称；列表继续展示 DCI 状态；当前不支持 `authorizationMode` 等额外筛选参数 |
| 获取下拉与复选项 | `GET /dictionaries/{dictType}`、`GET /tags?tagType=*` | IP 类型、资源来源、适用类型从字典加载；四类标签从标签接口加载 |
| 上传文件 | `POST /files` | 先上传文件，成功后将返回的 `fileId` 写入对应字段 |
| 上传评估报告 | `POST /ips/{ipId}/evaluation-reports` | 创建 IP 后可选调用；成功后刷新 IP 详情中的评估报告列表 |

- B02 表单完整展示本次新增字段，编辑回显与提交数据一致。

## 2026-09-08：平台基础配置、固定模板与下拉数据源

### A05 平台基础配置

1. 页面初始化调用 `GET /api/v1/admin/configs`，表格或分组表单绑定 `data.items[]` 的 `configKey`、`value`、`valueType`、`isSecret`、`hasValue`、`version`、`updatedAt`。
2. 非敏感项保存调用 `PATCH /api/v1/admin/configs/{configKey}`，请求体为 `value`、`reason`，请求头 `If-Match-Version` 使用当前行 `version`。
3. `isSecret=true` 时不展示输入框和实际值，仅展示“已配置/未配置”；外部密钥不允许由前端提交。

### A06 固定取消/退款模板

1. 列表调用 `GET /api/v1/admin/after-sale-templates?bizType={可选}&enabledOnly={可选}`，展示 `templateNo`、`templateName`、`bizType`、`versionNo`、`conditions`、`refundRule`、`returnFeeBearer`、`enabled`、`status`、`version`。
2. 新建调用 `POST /api/v1/admin/after-sale-templates`；商品显示退货费用承担方，活动隐藏该字段。`conditions`、`refundRule` 均提交 JSON 对象，具体时限、比例由平台管理员填写。
3. 不做“编辑并覆盖”操作。修改模板规则时调用 `POST /api/v1/admin/after-sale-templates/{templateId}/versions`，带 `If-Match-Version`；成功后刷新列表，旧版本会被后端自动停用。
4. 启停调用 `PATCH /api/v1/admin/after-sale-templates/{templateId}/status`，提交 `enabled`、`reason` 并带版本头。

### 统一下拉数据源

1. 地区选择器使用 `GET /api/v1/public/regions`，按需传 `level=NATION|PROVINCE|CITY|DISTRICT`、`parentCode`、`keyword`；不要继续使用旧的 `/dict-items`。
2. IP 四类标签使用 `GET /api/v1/tags?tagType=REGION|CULTURE|CATEGORY|COMMERCIAL`；后台维护标签使用 `/api/v1/admin/tags`。
3. 固定枚举使用 `GET /api/v1/dictionaries/{dictType}`。页面显示名称取接口 `name`，提交时使用 `code`，不得在前端硬编码中文枚举。

## 2026-09-08：A05 选项卡调整与固定字典

### A05 平台基础配置

1. 路由仍为 `/platform/config`，不增加侧边栏菜单。页面顶部使用三个选项卡：`平台参数`、`地区管理`、`标签管理`，默认选中平台参数。

5. A05 不提供固定枚举编辑。IP 类型、授权方式、DCI 状态、商品/活动状态、履约/售后规则等字段的选项统一调用 `GET /api/v1/dictionaries/{dictType}`；界面用 `name`，请求提交 `code`。地区选择仍使用公开地区查询接口，标签选择使用普通标签查询接口。

## 2026-09-08：统一文件上传与短期下载

1. 所有后台表单的图片、DCI 证书、权利证明、评估报告、委托书、作品文件和售后凭证均复用 `POST /api/v1/files`。请求类型为 `multipart/form-data`，只使用字段名 `file`；上传成功后取 `data.id` 写入页面状态，并在后续业务请求中作为 `fileId` 或 `fileIds` 提交。
2. 上传成功响应字段为 `id`、`fileNo`、`originalName`、`mimeType`、`fileSize`、`fileHash`、`securityLevel`、`uploadStatus`。前端不传 `fileRole`、`securityLevel`，不读取或保存 COS Bucket、`storageKey`、密钥。
3. 页面应在选择文件时做同等的格式/大小预检：图片仅 JPG/JPEG/PNG/WebP、最大 10MB；文档仅 PDF/DOC/DOCX/XLS/XLSX、最大 30MB；媒体仅 MP4/MP3/WAV、最大 200MB。服务端校验仍是最终依据；ZIP 等白名单外格式直接提示不可上传。
4. 私有文件预览/下载前调用 `POST /api/v1/files/{fileId}/download-url`，使用 `data.downloadURL` 打开，不缓存该地址；地址当前默认 10 分钟失效。读取元数据使用 `GET /api/v1/files/{fileId}`。
5. 错误提示：`FILE_SIZE_EXCEEDED` 提示文件超过限制；`FILE_TYPE_NOT_ALLOWED` 提示格式不支持；`FILE_CONTENT_INVALID` 提示文件内容与扩展名不一致；`FILE_UPLOAD_FAILED` 提示存储服务暂不可用并允许重新选择上传。

## 2026-09-09：B04/B05 授权方案与分账结构模板接口落地

后端已完成 B04/B05 可联调接口。前端将旧的 `/distribution-plans` 全部替换为 `/distribution-templates`：查询使用 `GET /api/v1/distribution-templates?enabledOnly=true`，创建使用 `POST`，详情使用 `GET /{templateId}`，编辑使用 `PATCH /{templateId}`，启停使用 `PATCH /{templateId}/status` 并带 `If-Match-Version`。模板字段只有 `distributionNo`、`distributionName`、`distributionType`、`items[].participantType`、`items[].sortNo`；不要再提交或展示模板比例、`required` 开关。模板中的所有参与方均为必选，已经被 IP 使用后，编辑或停用会收到 `AUTH_PLAN_BOUND_LOCKED`。

授权方案使用 `GET/POST /api/v1/auth-plans`、`GET /api/v1/auth-plans/{planId}`、`PATCH /api/v1/auth-plans/{planId}/draft` 与四个状态操作。创建字段以 `OpenAPI_v0.4.yaml` 的 `AuthPlanRequest` 为准，`authorizationMode` 只能为 `NORMAL_SHARE` 或 `EXCLUSIVE_BUYOUT`，但授权方案不提交 `distributionTemplateId`。审核接口仅由版权/合规使用，`result` 只能传 `PASS` 或 `RETURN`。B02/B03 选择与授权方式匹配的模板后，动态生成全部参与方的 IP 专属比例输入框，比例随 IP 入库和确权提交，模板本身绝不保存比例。

## 2026-09-09：已完成列表接口查询约束修正

## 2026-09-09：B03 DCI 处理与合规确权

1. B03 仅版权/合规可见。代办队列使用 `GET /api/v1/compliance/dci-assistance-requests`；联系人姓名、手机号仅为实际联系展示，禁止写入浏览器缓存、埋点、下载文件或控制台。
2. 代办处理使用 `POST /api/v1/compliance/dci-assistance-requests/{requestId}/handle`；DCI 核验使用 `POST /api/v1/ips/{ipId}/dci-verifications`；确权/退回使用 `POST /api/v1/ips/{ipId}/rights-reviews`。三个写操作都同时携带 `If-Match-Version` 和 `Idempotency-Key`。
3. 退回补充时 `comment` 为必填理由；确权确认时必须显示并提交最终授权方案、分账模板和全部参与方比例。得到存证成功回执后，`rights-reviews` 直接返回 `LISTED` 和 `mallVisible=true`，前端展示“已确权并已上架”。

## 原型同步约束

从本次起，每完成一个会影响页面展示、字段、状态、动作、权限或调用方式的后端接口任务，必须同时完成四项同步：更新 `OpenAPI_v0.4.yaml`、更新 `前端页面与接口字段绑定清单.md`、追加本文件和 `前端AI变更摘要.md`，并修改对应 HTML 原型页面。没有对应用户界面的纯内部任务，应在变更说明中明确“无前端原型修改”。前端 AI 开始开发前，以原型和 OpenAPI 的最新版本共同校验，不以旧页面文字推断接口。

## 2026-09-09：B02 城市 IP 入库接口落地

B02 的新建、编辑和回显分别使用 `POST /api/v1/ips`、`PATCH /api/v1/ips/{ipId}`、`GET /api/v1/ips/{ipId}`。编辑必须将详情返回的 `version` 放在 `If-Match-Version`；城市运营只可操作自己所属城市。创建和提交、DCI 代办、评估报告上传都要带符合规则的 `Idempotency-Key`，重复相同请求会收到首次结果并返回响应头 `Idempotency-Replayed: true`。

文件统一先通过 `POST /api/v1/files` 上传，再在 IP 请求中提交 `coverFileId`、`detailFileIds`、`rightDocuments[].fileId`、`dciCertificateFileId` 或评估报告 `fileId`。新增页勾选 DCI 代办时在 `POST /api/v1/ips` 同时提交 `dciAssistanceRequested=true` 和 `dciAssistanceRequest`，由服务端同一事务创建；此时不得提交 DCI 编号或文件。`POST /api/v1/ips/{ipId}/dci-assistance-requests` 仅用于已保存 IP 的后续补申请。DCI 缺失或代办中时，`POST /api/v1/ips/{ipId}/submit` 会返回 `422 IP_DCI_CERTIFICATE_REQUIRED`。比例输入框以百分数展示，提交时必须转换为 `distributionItems[].ratio` 的 `0~1` 小数字符串；模板所有参与方必须提交且总和为 `1.000000`。
## 2026-09-11：登录页取消角色选择

登录页不再提供角色下拉框，也不向 `POST /auth/login` 传 `loginType`。用户只提交账号、密码和图形验证码；登录成功后调用 `GET /auth/me`，根据服务端返回的角色、权限、菜单和数据范围初始化工作台并跳转首个可见页面。账号管理中的角色配置仍然保留，用于管理员维护账号权限，不等于登录时选择角色。
> 前端联调提醒：平台管理员查看 B04 全部授权方案、版权合规人员查看待审核方案，都必须调用 `GET /api/v1/auth-plans?enabledOnly=false`；不传参数等同于 `enabledOnly=true`，只返回已启用方案。只有城市 IP 选择可用方案时使用 `enabledOnly=true`。

## 2026-09-22：按资源和字段展示接口错误

统一请求层保留完整错误对象，不得只取 `message`。收到 404 时先读取 `code`、`data.resourceType`、`data.field`：若 `data.field` 存在，则定位并高亮对应表单控件，控件旁显示服务端 `message`；若不存在则显示页面级错误。收到 `STATE_TRANSITION_NOT_ALLOWED` 时读取 `data.currentStatus/action/reasonCode`，刷新详情后按当前状态重新计算按钮。未知错误码显示服务端 `message` 并附 `requestId` 供排查。`AUTH_FORBIDDEN` 只显示无权限，不探测资源存在性。
