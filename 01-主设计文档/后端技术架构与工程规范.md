## 1. 架构决策

| 项目 | 确认方案 | 说明 |
| --- | --- | --- |
| 总体架构 | 模块化单体 | 一期不拆微服务；一个 API 服务和一个 Worker 进程，共用代码模块与数据库 |
| 项目目录 | `G:\GO\xingyanshu-backend` | 后端源代码与 Gin + GORM 工程根目录 |
| Go Module | `xingyanshu-backend` | 一期不依赖尚未确定的线上域名 |
| 版本控制 | 本地 Git 仓库，`main` 为默认分支 | 当前不绑定远程仓库，后续提供地址后再关联 |
| Go 版本 | Go 1.25 | 以 Gin 1.12 要求的 Go 1.25+ 为边界，选用其最低支持主版本的最新补丁；不追逐最新版 Go |
| HTTP 框架 | Gin | REST API、路由分组、中间件、绑定校验 |
| 数据访问 | GORM + 原生 SQL | CRUD 使用 GORM；分账、库存/名额、结算、批量统计使用显式 SQL 与事务 |
| 数据库 | MySQL | 不建立物理外键；逻辑关联在服务事务校验 |
| 迁移 | 内置 SQL 迁移执行器 + 嵌入式 SQL 文件 | 禁止 GORM AutoMigrate；迁移编译进可执行文件，每一次表结构修改都有可追踪迁移 |
| 缓存 | Redis + go-redis | 验证码、刷新会话缓存、会话撤销、限流、幂等、短期锁 |
| 鉴权 | JWT + 服务端会话 | `golang-jwt/jwt/v5`，短 accessToken、刷新令牌轮换、`auth_session` 落库 |
| 密码 | bcrypt | `golang.org/x/crypto/bcrypt`；仅后台/创作者密码使用，消费者为短信登录 |
| 异步/定时 | 数据库任务表 + Worker 定时扫描 | 不引入 MQ；所有超时、补偿、重试可查询、可重入 |
| 日志 | Go `slog` + requestId | 结构化应用日志；业务审计单独写 `sys_audit_log` |
| API 契约 | OpenAPI 3.0.3 | `OpenAPI_v0.4.yaml` 为前后端契约；DTO 不自动生成业务逻辑 |
| 测试 | `testing` + `httptest` | 默认不调用外部服务；COS 与腾讯云 TMS 提供显式开关的真实测试，关键事务执行集成测试 |

## 3. HTTP、DTO 与错误规范

1. 所有 API 前缀使用 `/api/v1`，路径、字段和枚举必须符合 OpenAPI。
2. 统一响应：`code`、`message`、`requestId`、`data`；列表分页统一放在 `data.pagination`，字段错误使用 `fieldErrors[]`。
3. Handler 只做认证上下文读取、DTO 绑定与参数格式校验；业务状态、权限、事务和数据范围进入 Service。
4. Repository 不决定业务状态，不调用第三方，不输出 HTTP 错误；只负责数据库访问。
5. 请求链路必须生成/透传 `X-Request-Id`；日志、审计、错误响应和外部调用均关联该 ID。
6. 列表统一接受 `pageNo/pageSize`，最大 `pageSize=100`；排序字段必须白名单映射，禁止拼接任意 SQL。

## 4. 鉴权、会话与密码

### 4.1 认证方式

| 端 | 登录方式 | 密码/验证码处理 |
| --- | --- | --- |
| 管理后台/创作者 | 统一入口 `POST /auth/login`，账号密码 + 图形验证码 | 不传角色参数；服务端根据账号识别账号类型和 RBAC 角色；密码 bcrypt Hash；图形验证码 Redis 短期保存、一次性消费 |
| 消费者 H5 | 手机短信验证码 | 无密码；验证码仅用于注册和登录 |
| 外部回调 | HMAC 签名 | `X-Provider-Code`、`X-Request-Id`、`X-Timestamp`、`X-Signature` |

### 4.2 Token 与会话

1. 使用 `github.com/golang-jwt/jwt/v5`，一期采用 HS256；JWT 密钥仅来自部署服务器上的私有 YAML 配置文件，不提交仓库。生产环境可替换为 RS256，业务接口不变。
2. accessToken 默认 2 小时；refreshToken 默认 7 天，均配置化。
3. JWT Claims 只包含：`sub`、`sid`、`clientType`、`tokenVersion`、`iat`、`exp`、`jti`。
4. `auth_session` 记录会话 ID、主体、客户端、刷新令牌 Hash、Token 版本、过期时间与状态；数据库永不保存 refreshToken 明文。
5. 刷新时必须轮换 refreshToken；旧令牌立即失效。登出、账号停用、密码重置和风险处置时递增 Token 版本并撤销会话。
6. 后端每次请求读取当前账号状态、角色和数据范围，不能只依赖 JWT 内的历史角色声明。
7. Web 前端 accessToken 只在运行时内存使用；后台与创作者 Token 的 `clientType` 分别为 `ADMIN_WEB`、`CREATOR_WEB`，服务端禁止跨类型使用。当前 refreshToken 通过响应体传递；未来如切换 `HttpOnly + Secure + SameSite=Lax` Cookie，必须同步校验 Origin/CSRF。

### 4.2.1 当前实现：RBAC 与数据范围上下文

1. `RequireAdminAuthentication` 在 JWT、会话和账号校验通过后，从 `sys_user_role`、`sys_role`、`sys_role_permission`、`sys_permission` 读取当前有效角色和权限码，并将用户 ID、组织 ID、城市编码、数据范围、角色和权限写入 `CurrentAdmin` 请求上下文。
2. 业务路由使用 `RequireAnyPermission("权限码")` 声明至少一项所需权限；无权限统一返回 `403` 与 `AUTH_FORBIDDEN`。例如城市 IP 新建路由将使用 `IP_CREATE_CITY`。
3. 业务查询使用 `CurrentAdmin.ApplyDataScope` 按 `ALL`、`CITY`、`ORG`、`SELF` 自动增加固定列条件。列名仅允许由服务端代码传入并经过白名单格式校验，禁止把客户端字段、排序字段或任意 SQL 片段拼接为范围条件。
4. 该基础能力不替代业务归属和状态校验：写入时仍必须由领域服务覆盖 `created_by`、所属组织/城市等归属字段，不能信任请求体中的归属 ID。

### 4.3 密码与验证码

1. 使用 `bcrypt.GenerateFromPassword` / `CompareHashAndPassword`；成本因子先设为 12，并在部署压测后允许配置调整，但不得低于 10。
2. 密码明文不写日志、不落数据库、不返回响应；限制最大输入 72 字节。
3. 验证码按 `场景 + 手机号/IP` 限频；成功使用后立刻删除；错误次数达到阈值后短期冻结。

## 5. RBAC、数据范围、幂等与并发

### 5.1 服务端校验顺序

```text
解析 Token/会话
→ 检查账号状态与 Token 版本
→ 校验端类型和接口权限
→ 加载角色与数据范围
→ 查询对象并校验对象归属
→ 校验请求字段、乐观锁和状态机前置
→ 在事务内执行业务写入
→ 写状态历史、审计和异步任务
```

### 5.2 幂等

1. 创建授权订单、商品订单、预约、模拟支付、取消、发货、核销、退款、结算付款和存证重试强制 `Idempotency-Key`。
2. 使用 `internal/platform/idempotency.Execute`，由 `api_idempotency_record` 保存主体、接口、幂等键、请求 Hash、响应快照、状态和过期时间；默认保留 24 小时。
3. 同一键同一请求返回首次成功/失败结果；同一键不同请求返回 `409 IDEMPOTENCY_CONFLICT`。`Idempotency-Key` 仅允许 16-128 位字母、数字、点、下划线或连字符。
4. 幂等记录与主业务写入在同一事务内提交，避免“已扣库存但未记录幂等结果”；不得在具体模块重复实现幂等记录表逻辑。

### 5.3 锁与版本

1. 常规编辑和状态变更使用 `version` 字段/`If-Match-Version` 乐观锁。
2. 名额、SKU 库存、支付成功、退款、核销、分账使用 MySQL 条件更新或行锁事务；不要依赖前端校验。
3. Redis 短期锁只作为降低并发竞争的辅助，MySQL 条件更新才是正确性的最终保证。
4. 领域状态变更使用 `internal/platform/state.ValidateTransition`；拒绝时统一映射 `422 STATE_TRANSITION_NOT_ALLOWED`，成功时通过 `internal/platform/audit` 在同一事务写入状态历史和审计日志。

## 6. 数据库、迁移与事务

1. 使用内置迁移执行器按文件名顺序执行嵌入式 `internal/database/migrations/*.sql`，并在 `schema_migrations` 记录版本和 SHA256 校验和。已有一期 SQL 作为初始基线；后续只追加迁移，禁止修改已在环境执行过的迁移文件。
2. 禁止 `AutoMigrate`、禁止数据库物理外键、禁止通过 ORM 自动关联写入隐式修改业务对象。
3. GORM 查询默认显式选择字段；涉及敏感字段、复杂统计、批量更新和资金计算时使用原生 SQL 或 GORM `Transaction` 内的显式语句。
4. 所有跨表状态写入（如支付→授权/合同/名额，退款→售后/订单/冲销）必须在单个事务或可靠补偿链路中完成。
5. 金额字段使用 `DECIMAL`/字符串 DTO；计算使用整数分或十进制定点库，不能用 `float32/float64`。

## 7. Redis 与任务系统

| Redis Key 类别 | 用途 | 建议 TTL |
| --- | --- | --- |
| `captcha:*` | 图形验证码 | 5 分钟 |
| `sms:*` | 短信验证码/错误次数/限流 | 5-10 分钟 |
| `session:revoked:*` | 会话撤销或 Token 版本缓存 | 至会话过期 |
| `idem:*` | 高频接口幂等快速命中 | 与数据库幂等记录一致 |
| `rate:*` | 登录/公开接口限流 | 按接口策略 |
| `lock:*` | 短时竞争辅助锁 | 30-60 秒，必须自动过期 |

Worker 使用 `job_task`（任务类型、对象、执行时间、状态、尝试次数、租约、最后错误）与 `job_execution_log`。至少实现：授权/订单待支付关闭、授权到期、活动结束过期、订单自动完成、检测/存证重试、订单完成/核销后的分账补偿。任务必须可重入、可人工触发和可观测。

## 8. 外部服务 Adapter

所有外部调用定义接口并提供 `real`、`mock` 两类实现；业务模块只依赖接口，不直接依赖服务商 SDK。

| Adapter | 必须能力 | 失败处理 |
| --- | --- | --- |
| SMS | 发码、请求号、状态 | 限频/失败不生成可用验证码 |
| Identity | 个人/企业/工作室核验 | 认证中/失败禁止购买和创作 |
| ContentSafety | 腾讯云 TMS 文本检测、请求号、摘要 | 已接入真实 Adapter；`REVIEW`、`BLOCK` 或异常均阻断当前提交 |
| FileStorage | 上传、Hash、签名下载 | 不暴露存储键；私有文件按对象权限签发 |
| Payment | 支付下单、支付/退款回调、流水号 | 测试使用 Mock；生产使用真实服务，业务流水幂等 |
| ESign | Word 模板填充、签署结果、签署 PDF | 一期使用 Mock；真实服务接入后验签回调，重复/异常不变更合同状态 |
| Logistics | 轨迹、签收、回调验签 | 重复/乱序回调不回退终态 |
| Evidence | 提交、查询、回执 | 无回执不成功；记录失败并任务重试 |

外部回调必须在进入业务逻辑前校验时间窗口、请求 ID、HMAC 签名和服务商编码；回调原文加密/脱敏归档，不在普通日志中泄露。

## 9. 日志、审计、监控与安全

1. `slog` 日志至少包含：时间、级别、requestId、模块、接口、主体 ID、耗时、错误码；密码、证件、手机号完整值、地址完整值、Token 和密钥必须脱敏。
2. `sys_audit_log` 记录登录、权限、高风险状态变更、合同/素材下载、退款、冻结、结算、导出、存证重试等操作。
3. 一期不提供应用自定义健康检查接口；进程健康与发布状态由现有 Rancher 机制统一处理。
4. 指标至少覆盖：HTTP 错误率/耗时、验证码/登录失败、外部服务失败、任务积压、库存/名额冲突、支付/退款/存证失败、分账异常；请求耗时超过 1 秒记录慢请求日志并触发既有告警链路。
5. 生产环境强制 HTTPS；CORS 使用 `gin-contrib/cors` 中间件，配置位于私有配置文件的 `cors.allowed_origins`。测试/开发环境可使用 `*` 便于联调，生产环境必须使用精确前端来源白名单，程序会拒绝 `*` 或空配置；允许方法为 `GET/POST/PATCH/PUT/DELETE/OPTIONS`，允许请求头至少包括 `Authorization`、`Content-Type`、`X-Request-Id`、`Idempotency-Key`、`If-Match-Version`。当前刷新令牌不使用跨域 Cookie，`AllowCredentials=false`；未来启用 HttpOnly Cookie 后必须同步限制精确来源、Origin 和 CSRF。请求体大小、上传 MIME/大小、公开接口频率均受限制。

## 10. 测试与质量门禁

1. Service 单元测试覆盖正常、越权、状态冲突、幂等、并发和外部失败。
2. Handler 使用 `httptest` 覆盖 OpenAPI 的主要成功/失败响应；测试中固定 `requestId` 便于断言。
3. 关键事务使用真实 MySQL 测试库或容器化测试，至少验证库存/名额不超卖、退款不重复、核销不重复、分账不重复。
4. Adapter 使用 Fake/Mock，测试回调验签、重复、乱序、超时和重试。
5. 合并前固定执行：`go fmt`、`go vet`、单元测试、接口测试、OpenAPI 变化检查、数据库迁移从空库执行检查。

## 12. 已确认技术参数

### 12.1 文件、COS 与外部服务

| 项目 | 已确认规则 |
| --- | --- |
| COS | 腾讯云 COS 私有桶；后端按文件用途和权限签发短期 URL |
| 上传类型/大小 | 图片 JPG/JPEG/PNG/WebP，单文件最大 10MB；文档 PDF/DOC/DOCX/XLS/XLSX，最大 30MB；媒体 MP4/MP3/WAV，最大 200MB；拒绝压缩包、可执行文件和未知 MIME 类型 |
| 上传链路 | 前端将 `multipart/form-data` 文件提交到后端 `POST /files`；后端先校验扩展名、探测 MIME 和大小，再流式上传 COS，同时计算 SHA-256。业务接口仅保存后端返回的 `fileId`，不直传 COS，也不接触存储键 |
| 孤立文件处理 | 上传开始、成功或失败均记录文件状态和审计；一期不做物理删除，自动化测试对象统一使用 `xingyanshu/test/autotest/` 前缀并建议由 COS 生命周期规则清理 |
| 大文件续传 | 一期不支持断点续传；上传中断后由前端重新发起上传 |
| 媒体预览 | 图片由异步任务生成缩略图；视频不做转码或自动截帧，须由创作者上传封面图片 |
| 上传校验 | 一期校验 MIME、扩展名、大小和文件 Hash；不接病毒扫描 |
| 下载 URL 有效期 | 商品/活动公开图片 1 小时；合同、权利证明、作品源文件、售后凭证 10 分钟 |
| 测试环境 Adapter | 文件存储使用腾讯云 COS 私有测试桶；文本检测使用腾讯云 TMS 真实测试凭据；短信、快递100、实名、支付、电子签章和存证仍未接入 |
| 生产环境 Adapter | COS、腾讯云 TMS、腾讯云短信、快递100、实名、支付、电子签章、存证均须使用真实对外 API；任一已启用 Adapter 配置为 Mock 时应用拒绝启动 |
| 当前开发阶段 | `test` 环境的文件服务和文本检测可显式调用真实腾讯云服务；其他未接入的外部 Adapter 不得冒充真实成功；不得以测试配置作为生产上线配置 |
| 上线前外部确认 | 微信支付商户模式与域名/回调地址/凭证、电子签章服务商、实名服务商、存证链平台及各服务生产凭证须逐项确认并写入 `config/production.yaml`；未完成任一项不得发布生产环境 |
| 敏感检测异常 | 腾讯云 TMS 不可用、超时或返回 `REVIEW/BLOCK` 时，当前提交必须阻断；业务库只保存 Hash 与审核摘要，不保存原始敏感文本 |
| 合同与授权凭证 | 合同生效或授权完成时基于平台提供的法务模板生成正式 PDF，存入 COS 私有桶；再创建存证任务。Mock 存证只可返回明确的模拟状态，不得伪造真实存证成功 |

### 12.2 运维、迁移与初始化

| 项目 | 已确认规则 |
| --- | --- |
| 环境 | 至少独立的 `test` 与 `production`；不得共用数据库、Redis 命名空间或密钥 |
| 发布 | Rancher 现有发布机制负责进程守护；交付 Linux amd64 可执行文件、配置样例、迁移和启动说明 |
| 可执行文件 | 交付单一 `xingyanshu` 可执行文件，使用 `xingyanshu server`、`xingyanshu worker`、`xingyanshu migrate`、`xingyanshu bootstrap` 分别启动服务、任务进程、数据库迁移和基础数据初始化 |
| 构建方式 | 使用 `CGO_ENABLED=0 GOOS=linux GOARCH=amd64` 交叉编译静态 Linux 可执行文件 |
| 开发与构建命令 | 本地 Windows 使用 `go run`；仓库同时提供 `Makefile` 和 PowerShell 构建脚本，适配 Linux 与 Windows 开发环境 |
| 数据备份 | MySQL 和 Redis 备份由现有运维/Rancher 平台负责；应用提供迁移与恢复说明 |
| 生产迁移 | 仅发布阶段执行 `xingyanshu migrate`；API 与 Worker 启动时禁止自动迁移 |
| 初始管理员 | 迁移完成后执行一次 `xingyanshu bootstrap`；从服务器私有配置文件读取平台组织与初始管理员信息，按组织编码、角色编码和账号名幂等创建；后续账号均由后台管理 |
| 审计保留 | 业务审计日志在线保留 3 年；应用运行日志由现有日志平台保留 180 天 |
| 公共接口限流 | 一期暂不单独实现公共接口限流；保留 Redis 限流中间件扩展点，并由负载均衡/WAF 承担基础防护 |
| 数据库迁移 | 使用内置迁移执行器管理版本化 SQL；按顺序执行并记录已执行版本及文件 SHA256，不用于旧系统数据迁入 |
| 迁移修订 | 已发布迁移只向前新增，禁止修改或回滚；问题通过新的迁移脚本修复 |
| 数据结构基线 | 严格以已确认 SQL 与字段字典为准；字段和索引变更必须新增迁移脚本，禁止直接修改生产数据库 |
| 服务端口 | 默认监听 `8080`，允许通过部署配置覆盖 |
| OpenAPI 文档 | 生产环境默认关闭在线 Swagger/OpenAPI 页面；测试环境开放 |
| 跨域策略 | `config/test.yaml` 可使用 `cors.allowed_origins: ["*"]`；生产私有配置必须填写精确来源白名单 |
| 可信代理 IP | 一期不配置可信代理 IP 段，也不依赖转发头识别真实客户端 IP；后续接入时再由运维提供负载均衡代理网段 |
| 配置与密钥 | 不使用 Rancher 环境变量；生产密钥写入部署服务器的私有配置文件（建议 `config/production.yaml`），任何密钥不得提交仓库；Linux 文件归运行账户所有，权限设为 `600` |
| 配置分层 | 本地开发、测试、生产分别使用私有 YAML 配置；测试 COS 凭据直接写入不提交仓库的测试配置。上传策略在 YAML 合法修改后每 2 秒热加载；数据库、JWT、COS Bucket 和密钥修改必须重启服务 |
| 测试数据 | 测试环境使用独立测试数据库和 Mock 数据，完整测试前可重置；生产库禁止使用测试脚本清库 |
| 数据删除 | 订单、合同、授权、结算和审计等业务记录使用逻辑删除或状态失效，不做物理删除；一期不提供用户注销和个人信息清理，仅支持后台冻结账号 |
| Mock 控制 | 不建设 Mock 控制台；全部 Mock 行为仅由测试或私有部署配置文件控制 |
| Worker 并发 | 默认单 Worker 进程、最多并发执行 3 个任务；通过私有配置文件调整，关键任务仍以 Redis 锁防重 |

### 12.3 文档导出与异步任务

| 项目 | 已确认规则 |
| --- | --- |
| 合同模板 | 合同、授权书和授权凭证采用平台提供的 Word 模板，以 `${variables}` 占位符填充业务字段；法务条款以模板为准，开发仅填充已确认的业务字段 |
| 模板管理 | Word 模板存放在 `assets/templates/` 并纳入 Git 版本管理；正式模板更新须随代码评审和版本记录提交 |
| 空占位符 | 占位符没有对应值时填充空字符串，禁止在生成文件中保留 `${variables}` 原文 |
| 电子签章 | 测试环境使用 ESign Mock Adapter；生产环境在授权支付成功后调用真实电子签章 API 并取得签署 PDF。两种环境均不提供用户在线签署；真实服务按服务商官方文档实现回调验签与接口参数 |
| 签章失败 | 签章或合同生成失败时，授权订单保持“已支付、合同生成中”，由 Worker 自动重试；创作者不得因此取消或退款 |
| 正式合同 | 测试环境的模拟签署 PDF、生产环境的真实签署 PDF 均作为用户可见的唯一合同版本；原始 Word 仅保存为生成记录，不对用户开放 |
| 签章审计 | 合同签署结果、签章订单号、回执文件 URL、签署时间写入审计日志和存证材料；未来真实回调验签失败、重复或异常时不得变更合同状态 |
| 文件保留 | 合同、授权凭证和存证材料在 COS 至少保留 5 年；期满后由平台人工决定是否清理 |
| 后台导出 | 统一生成 `.xlsx`；大数据量导出走异步任务，并保存下载记录 |
| 任务执行 | Worker 通过数据库任务表领取任务，以 Redis 分布式锁避免重复执行；失败按指数退避自动重试 |
| 支付 Adapter | 测试环境使用 Mock；生产环境接入真实支付 API。数字人民币为后续可选支付渠道，不作为一期真实支付接入的前置条件 |
| 微信支付业务规则 | 生产环境订单款项先进入平台微信支付商户账户；退款统一原路退回；`time_expire` 与业务待支付关闭时间均为 30 分钟，由 Worker 主动关单 |
| 实名 Adapter | 测试环境使用固定测试证件号或企业统一社会信用代码的 Mock；生产环境必须接入真实第三方实名 API，Mock 结果不得进入生产业务链路 |
