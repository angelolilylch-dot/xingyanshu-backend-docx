## 记录规则

1. 每完成一个 API 任务，按“接口记录模板”追加一节；一个接口至少记录一个成功和一个常见失败示例。
2. 请求与响应示例使用脱敏测试数据；不得写入密码、Token、验证码、真实手机号、密钥或真实第三方回调签名。
3. 请求地址必须包含 HTTP 方法和完整的 `/api/v1` 路径；写接口同时记录鉴权、幂等键、乐观锁或状态前置条件。
4. 若任务只实现公共能力、数据迁移或适配器，未新增对外路由，必须明确标记“无新增接口”，不得虚构测试地址。

- **事务边界：** 同一事务创建唯一支付流水，将订单置为 `PAID`，把有限名额预占转为正式占用，并创建有效授权、范围记录及合同生成任务。重复请求只返回已有结果，不重复创建数据。

- **前端调用：** 支付成功后进入购买记录/授权详情；合同未生成时展示“生成中”，`downloadReady=true` 后调用合同下载接口。存证状态独立展示，不得因存证失败显示支付失败。
- **关键错误：** `AUTH_ORDER_NOT_FOUND`、`AUTH_ORDER_PAYMENT_EXPIRED`、`STATE_TRANSITION_NOT_ALLOWED`、`AUTHORIZATION_NOT_FOUND`、`CONTRACT_NOT_READY`、`CERTIFICATE_NOT_READY`、`FILE_NOT_FOUND`、`FILE_DOWNLOAD_URL_FAILED`。
- **测试结果：** 已覆盖真实 TCP HTTP、真实 MySQL、重复支付幂等、有限/不限名额、PDF 文件生成、合同/凭证下载、存证成功、存证最终失败不回滚、合同生成失败不回滚、迁移和编译验证。生产微信支付 V3 不属于本任务完成范围，继续由 `API-FND-05-R1` 承接。

### 2. 新增后台账号

- **请求：** `POST /api/v1/admin/accounts`，请求头为 `Authorization: Bearer {accessToken}`、`Content-Type: application/json`。
- **请求体：** `username` 为 2 至 50 位字母、数字、下划线或连字符，首尾必须是字母或数字；`initialPassword` 为 8 至 64 位且仅写入不回显；`displayName` 必填且最长 128 位；`mobile` 可空，填写时必须是 11 位数字；`orgId` 为已启用组织 ID 字符串；`roleCode` 为已启用角色编码；`dataScope` 仅支持 `ALL`、`CITY`、`ORG`、`SELF`。一期只绑定该一个角色，不传 `Idempotency-Key`。

## API-FND-02 通用响应、错误码、幂等、状态与审计基座

- **状态：** 已完成
- **请求地址：** 无新增对外路由。本任务提供后续写接口调用的公共组件。
- **鉴权与前置：** 具体接口先完成 JWT、权限和数据范围校验；需要幂等的写接口再读取 `Idempotency-Key`，需要乐观锁的编辑、审核和状态接口读取 `If-Match-Version`。
- **涉及数据表：** `api_idempotency_record`、`biz_status_history`、`sys_audit_log`。
- **数据库迁移：** `000006_add_api_idempotency_record.sql` 创建 MySQL 幂等记录表；`000007_allow_pending_idempotency_record.sql` 允许处理中记录的 `completed_at` 为空。两份迁移已在本地 `xingyanshu_test` 成功执行。

### 1. 后续写接口接入方式

1. Handler 绑定并校验请求 DTO 后，取得当前登录主体、请求方法、请求路径和 `Idempotency-Key`；订单、支付、退款、发货、核销、结算、存证重试等动作必须使用该键。
2. 调用 `idempotency.Execute(ctx, db, scope, key, requestBytes, handler)`。`scope` 由主体类型、主体 ID、HTTP 方法、路由路径组成；`requestBytes` 使用已校验 DTO 的稳定 JSON 序列化结果。
3. 回调 `handler(tx)` 只能使用传入的事务 `tx` 写入主业务、`biz_status_history`、`sys_audit_log` 和首次响应数据；回调成功后，框架把脱敏后的响应快照更新为 `COMPLETED`。
4. 返回 `replayed=true` 时 Handler 仍按保存的 HTTP 状态、业务码、消息和 `data` 输出响应，但不得再次调用第三方或重复修改业务数据。

## API-IP-02：DCI 处理、合规确权与测试存证

### 0. 版权/合规主工作队列

- **查询：** `GET /api/v1/compliance/ips/pending?keyword={可选}&dciCertificateStatus={UPLOADED|VERIFIED，可选}&pageNo=1&pageSize=20`。只返回 `PENDING_COMPLIANCE` IP，按最近处理时间从早到晚排列，便于优先处理积压事项。
- **返回与下一步：** 每项返回 `id/version/ipNo/ipName/mainCityOrgId/mainCityOrgName/rightHolderNameMasked/dciCertificateStatus/authPlanVersionId/authPlanName/distributionTemplateId/distributionTemplateName/hasEvaluationReport/nextAction/updatedAt`。`nextAction=VERIFY_DCI` 表示先调 DCI 核验；`nextAction=CONFIRM_RIGHTS` 表示可进入权属与授权边界确认；其他异常资料状态为 `COMPLETE_DCI_MATERIAL`。点击项目后再通过 `GET /api/v1/ips/{ipId}` 读取完整材料。
- **边界：** 本队列是版权/合规的首要日常入口；DCI 代办只作为第二页签的辅助待办，不会影响待审核 IP 的展示。

### 1. DCI 代办处理

- **查询：** `GET /api/v1/compliance/dci-assistance-requests?handlingStatus={可选}&keyword={可选}&pageNo=1&pageSize=20`。仅版权/合规可调用，返回完整 `contactName/contactMobile` 以便联系；服务端加密存储，读取操作写入审计日志，前端不得缓存、导出或记录到控制台。
- **处理：** `POST /api/v1/compliance/dci-assistance-requests/{requestId}/handle`，请求头带 `If-Match-Version`、`Idempotency-Key`，请求示例：`{"handlingStatus":"CONTACTED","handlingNote":"已联系申请人"}`。只允许 `CONTACTED`、`PROCESSING`、`COMPLETED`、`CLOSED`，已完成或已关闭的请求不能再次变更。
- **资料包下载：** `POST /api/v1/compliance/dci-assistance-requests/{requestId}/application-package`，仅版权/合规可调用，必须带 `Idempotency-Key`，请求 `{"includeEvaluationReport":false}`。服务端生成私有 ZIP：`00_DCI代办申请资料.md`、`02_IP作品资料/IP作品说明.md`、权属证明与作品附件；勾选时附带有效评估报告。返回 `packageFileId/fileName/downloadUrl/expiresAt`；ZIP 内含联系人明文但响应和审计不含该明文。已关闭的代办申请或缺少权属证明、作品资料时不得生成。

### 2. DCI 核验与权属确权

- **DCI 核验：** `POST /api/v1/ips/{ipId}/dci-verifications`，请求为 `{"result":"PASS","comment":"DCI证书核验通过"}` 或 `{"result":"RETURN","comment":"证书编号与文件不一致"}`，并带版本与幂等头。通过仅使 DCI 变为 `VERIFIED`；退回使 IP 进入 `SUPPLEMENT_REQUIRED`、DCI 变为 `REJECTED`。
- **确权/退回：** `POST /api/v1/ips/{ipId}/rights-reviews`。`RETURN` 必须提交 `comment`，可提交 `supplementItems`；`CONFIRM` 必须附带最终 `authPlanVersionId`、`distributionTemplateId`、`distributionItems[]`，比例覆盖全部模板参与方且合计 `1.000000`。DCI 未核验时无法确认。
- **存证：** 确权确认先将 IP、权利证明、评估报告、关联文件 Hash、方案及最终比例组成确定快照，提交测试环境 Mock 存证。取得 `MOCK-RCPT-*` 回执及 `MOCK-TX-*` 链上交易/存证哈希后才写正式 `ip_auth_binding`，并在同一事务中进入 `LISTED`、开放商城可见；成功响应返回 `evidenceReceiptNo` 和 `evidenceTransactionHash`，后者供 B03 展示和复制；存证异常返回 `502`，IP 保持待合规状态。

### 3. 本阶段边界

确权成功后的商城上架由 `rights-reviews` 自动完成；IP 暂停、恢复、下架接口均已实现，风险处置按当前范围暂缓。

- **腾讯云配置：** `content_safety.provider=tencent_tms`、`region=ap-guangzhou`、`biz_type=ip_center`、`secret_id`、`secret_key`、`timeout=10s`。密钥支持本机私有 YAML 或本机环境变量展开，不能提交 Git、不能返回给前端、不能写入普通日志。
- **内部调用：** `ContentSafetyProvider.Moderate(ctx, Request)` 接收原始待审文本、系统生成的 `dataId`、可选会话编号和语言；SDK 自动将 UTF-8 文本 Base64 编码后调用腾讯云 `TextModeration`。返回 `provider=TENCENT_TMS`、`providerRequestNo`、`decision`、`label`、`subLabel`、`score`。后续业务只保存文本 SHA-256、结果摘要和腾讯请求号，不保存敏感词原文。
- **处理规则：** 腾讯 `Pass` 映射为 `PASS`；`Review` 和未知建议映射为 `REVIEW`；`Block` 映射为 `BLOCK`。`REVIEW`、`BLOCK`、调用超时、网络异常和返回不完整均阻断本次业务提交，并由 IP 模块写入 `content_detection_record`、状态历史和审计日志。
- **存证 Mock：** `test` 环境的 `EvidenceProvider` 先创建 `PENDING_CHAIN` 记录，再由 `POST /api/v1/integrations/evidence/callbacks` 模拟第三方异步通知。回调必须提供 `X-Evidence-Timestamp` 和 `X-Evidence-Signature`，签名为 `HMAC-SHA256(timestamp + 原始请求体)`；成功回调必须有 `receiptNo`。同一请求号、相同结果的重复回调不重复变更状态。生产环境不得使用 `mock`。
- **测试：** 单元测试覆盖结果映射和未配置存证服务不得成功。显式设置 `XINGYANSHU_RUN_TMS_TESTS=1` 以及腾讯云测试凭据后，已真实调用腾讯云完成中文正常文本检测；日常 `go test` 不触发外部请求。
