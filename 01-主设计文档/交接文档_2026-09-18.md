## 2. 本次最后完成的功能：新增 IP 时一并申请 DCI 代办

### 2.1 已落地的用户流程

1. 城市运营进入 B02「城市 IP 管理」→「新增 IP」。
2. DCI 区域提供 `dciAssistanceRequested`（是否申请 DCI 代办）复选框；**不设置单独的“申请 DCI 代办”按钮，也不要求用户先保存草稿再申请**。
3. 勾选后展开 `dciAssistanceRequest`：
   - `contactName`（联系人姓名，必填）
   - `contactMobile`（联系人手机号，必填）
   - `preferredContactTime`（方便联系时间，可选）
   - `requestNote`（代办说明，可选）
4. 用户只点击一次“保存 IP”，调用 `POST /api/v1/ips`。
5. 后端在**同一个数据库事务**内创建 IP、关联资料、初选方案/比例，以及 `ip_dci_assistance_request`（DCI 代办申请）。
6. 返回 IP `id/ipNo/status/version/dciCertificateStatus`，并在已创建代办时返回 `dciAssistanceRequestId/dciAssistanceRequestNo`。

创建后的 IP 后端状态仍是 `DRAFT`（草稿），这是状态机内部状态，不代表前端要展示或点击“保存草稿”这个独立动作。

### 2.2 DCI 代办与 DCI 证书的互斥规则

| 前端行为 | 后端校验 |
| --- | --- |
| 勾选 DCI 代办：禁用并清空 `dciCertificateNo/dciCertificateFileId` | 同时传代办标识与任一证书字段，返回 `VALIDATION_FORMAT_INVALID` |
| 填写 DCI 编号或上传 DCI 文件：自动取消代办，清空联系人资料 | `dciAssistanceRequested=true` 时，必须提供联系人姓名、手机号 |
| 未勾选代办也未上传证书：可以保存 IP | 不能提交审核 |

`POST /api/v1/ips/{ipId}/dci-assistance-requests` 仍保留，但用途已收窄为：**IP 已保存后，城市运营后来才决定补申请代办**。

### 2.3 后续 DCI 流转

- `ASSISTANCE_REQUESTED`（已申请代办）只表示版权/合规人员收到线下代办待办，不等于有 DCI 证书。
- 版权/合规在 B03 的「DCI 代办」页签查看待办、联系申请人、线下办理；可生成私有 ZIP 申请资料包。
- 办理完成后，城市运营补传 DCI 编号和文件，使 DCI 状态为 `UPLOADED`（已上传待核验）。
- `POST /ips/{ipId}/submit` 要求：DCI 编号非空、文件存在、`dciCertificateStatus=UPLOADED`；否则返回 `IP_DCI_CERTIFICATE_REQUIRED`。
- 版权/合规调用 `POST /ips/{ipId}/dci-verifications` 核验；通过后状态为 `VERIFIED`。

## 3. 已完成的核心业务口径

### 3.1 IP 确权与商城状态

- 不提供人工上架接口；`POST /ips/{ipId}/list` 返回 404 是正确行为。
- 版权/合规在 `POST /ips/{ipId}/rights-reviews` 执行 `CONFIRM`，DCI 已核验、授权方案/分账/商城资料满足且存证成功后，IP 在同一事务直接变为 `LISTED`（已上架）并 `mallVisible=true`。
- 平台管理员可执行：
  - `POST /ips/{ipId}/pause`：`LISTED → PAUSED`
  - `POST /ips/{ipId}/resume`：`PAUSED → LISTED`
  - `POST /ips/{ipId}/delist`：`LISTED/PAUSED → DELISTED`
- 三个状态变化均需要 `comment`、`If-Match-Version`、`Idempotency-Key`。
- 风险处置流程尚未开发，用户明确要求暂时搁置。

### 3.2 IP 价格、授权方案与分账

- `suggestedTransactionPriceAmount`：IP 建议交易价，IP 创建时必填；确权时由版权/合规确认并锁定。
- `evaluationSuggestedPriceAmount`：评估建议价格，评估报告表单可选填写，仅作参考，非必填。
- 授权方案是权利范围/期限/方式方案，不配置 IP 交易价。
- 分账模板只定义参与方，不定义比例；IP 提交/确权时的 `distributionItems[].ratio` 才是收益比例。
- 参与方统一为：`RIGHT_HOLDER`（原始权利人）、`CREATOR`（创作者）、`CITY_OPERATOR`（城市运营）、`PLATFORM`（平台）。比例用 `0~1` 小数，必须覆盖模板参与方并合计 `1.000000`。

### 3.3 C02 创作者 IP 商城

C02 已完成并有真实 MySQL HTTP 测试。已具备：

- 商城列表、详情、购买资格预览；
- 仅展示已上架、商城可见、方案有效的 IP；
- 列表字段和筛选已补齐；`listedAt` 使用最近一次进入 `LISTED` 的状态时间；
- 独家买断资格已修复：若已有其他创作者的有效独家授权，返回 `canPurchase=false`，购买预览返回 `AUTHORIZATION_QUOTA_SOLD_OUT`；并发购买的最终锁定必须由后续 C03 订单创建事务处理。

### 3.4 DCI 代办申请资料 ZIP

已完成接口：

```text
POST /api/v1/compliance/dci-assistance-requests/{requestId}/application-package
```

- 仅 `COPYRIGHT_COMPLIANCE`（版权/合规人员）可用；需要 `Idempotency-Key`。
- 请求：`includeEvaluationReport`（是否附带有效评估报告）。
- 生成私有 ZIP：代办申请 Markdown、IP 作品说明、权属证明、作品附件，以及可选评估报告。
- 返回：`packageFileId/fileName/downloadUrl/expiresAt`。
- 联系人明文只存在 ZIP 内；响应与审计不写明文，联系人数据加密存储。
- 文件存储接口已增加 `Get`，COS 实现只读取私有对象。

### 3.5 登录和密码（已完成）

- 后台登录页面不再要求选择角色，登录请求不传 `loginType`；登录后以 `GET /auth/me` 返回的角色、权限、菜单、数据范围决定工作台。

   - 后端 AI 开发包；
