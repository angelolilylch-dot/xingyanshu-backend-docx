## 1. 角色与数据隔离

| 角色 | 首期权限 |
| --- | --- |
| 城市运营者 | 导入本城市职业模特名单、发送短信通知、管理通用二维码、查看进度和处理异常 |
| 入库者 | 在独立 H5 登录、实名、签署采集与入库授权、上传资料、查看档案、补采、申请删除 |
| 平台管理员 | 处理实名异常、质检异常、删除申请；唯一可查看实名结果、受控素材预览及敏感访问审计 |

- 独立 H5 会话类型为 `AVATAR_H5`，不属于消费者端。
- 独立业务表组不复用 `consumer_account`、消费者会话、订单、地址簿、活动预约或普通文件登记表。
- 仅可引用既有组织、城市与运营者账号作为归属/审计主体；图片、视频、音频等由独立 `avatar_asset` 管理。

## 2. 两种注册入口

### 2.1 短信通知

城市运营者对已导入人员发送建档提醒。短信可带直达入口，但手机号登录后仍须实名并匹配名单。

### 2.2 通用二维码

每个城市配置长期有效的通用二维码，用于海报、展架和群公告；可由城市运营者暂停或轮换，默认不设到期日。二维码只标识城市，不代表人员身份：扫码者仍必须完成短信登录、实名核验，并以实名姓名、登录手机号、性别与导入名单三项一致完成匹配。任一项不一致即拒绝建档，不暴露具体不一致原因，仅提示联系该城市配置的运营电话。

```text
短信通知 / 通用二维码
→ 独立 H5 短信登录
→ 实名核验
→ 姓名、手机号、性别三项匹配城市运营者已导入名单
→ 签署采集与入库授权
→ 采集、质检、加密归档
```

## 3. 人员与采集规则

- 首期人员类别固定为 `PROFESSIONAL_MODEL`（职业模特）；导入模板不展示类别列，数据默认写入该值。
- 实名采用第三方核验，平台保存必要的结果、时间和服务商流水，不默认保存身份证原图。
- 默认仅面向成年人；未成年人需在后续独立任务中增加监护人核验与授权链路。
- 后台工作人员导入名单的源字段为姓名、身份证号、性别、手机号。名单只有在后台实名核验通过后才可成为有效建档名单；身份证号仅限后台受控处理，独立 H5 永不采集、展示或缓存完整身份证号。
- 采集资料：8 张多角度人脸照片、约 40 秒朗读视频、可选体型资料。
- 自动质检通过直接加密归档；仅质检异常、抽检或风控命中时进入平台管理员人工复核。
- 建档完成仅代表资料已质检并加密归档，不赋予城市运营者任何对外使用权。
- 首期全部城市统一保存 1 年，自档案首次归档时起算；到期自动进入清除或不可逆匿名化流程。该期限、必要性及删除例外须在个人信息保护影响评估和授权文本中固定。

## 5. 状态机

```text
名单：IMPORTED → ACTIVATED → COMPLETED
                 ├→ EXPIRED
                 └→ REVOKED

档案：NOT_STARTED → REAL_NAME_PENDING → CONSENT_PENDING → COLLECTING
→ SUBMITTED → AUTO_QUALITY_CHECKING → MANUAL_REVIEW → ARCHIVED

异常：REAL_NAME_REJECTED / QUALITY_REJECTED / RESHOOT_REQUIRED /
      SUSPENDED / DELETION_REQUESTED / DELETED
```

## 7. 安全与验收底线

- 通用二维码不能绕过名单匹配；短信和二维码均须经过独立 H5 登录、实名核验及姓名/手机号/性别三项匹配。
- 城市运营者仅限本城市数据范围，默认无原始素材下载能力。
- 素材以加密存储键、哈希、明确保留期限和访问等级管理；仅平台管理员可申请短时受控预览，且全程留痕。
- 城市运营者只能导出本城市去标识化进度清单；原始归档包仅平台管理员以明确用途申请。归档包密码只可展示一次；遗失后旧包下载会被撤销，必须重新生成新任务及新密码。
- 删除申请须形成申请、审核、清除/匿名化/保留例外的可审计闭环。
- 上线前须完成人脸、声音等敏感个人信息处理的个人信息保护影响评估；采集授权与后续使用授权不得混同。
