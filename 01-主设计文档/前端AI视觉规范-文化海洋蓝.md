# v0.5 前端 AI 视觉规范：文化海洋蓝

适用原型：[星恒云创版权二创平台一期MVP角色原型_v0.5专业版.html](星恒云创版权二创平台一期MVP角色原型_v0.5专业版.html)

## 1. 视觉定位

专业、可信、克制的文化版权资产运营后台。以“文化海洋”为视觉隐喻，使用深海蓝承载品牌与导航，用海湾蓝表达行动，用冷米白承载内容。潮汐线和远处灯塔只作为品牌识别，不作为装饰性插画堆叠。

## 2. 配色

| 变量 | 色值 | 用途 |
| --- | --- | --- |
| `--deep` | `#073763` | 登录品牌区、后台导航、标题强调 |
| `--deep-2` | `#0B4778` | 深色悬停和辅助深色 |
| `--blue` | `#0B6FB8` | 主按钮、链接、选中态、进度态 |
| `--blue-2` | `#0B5CA5` | 主按钮悬停 |
| `--pale` | `#EEF7FB` | 信息提示、浅蓝区域 |
| `--paper` | `#F8FAF9` | 页面背景 |
| `--ink` | `#193247` | 主文字 |
| `--muted` | `#708596` | 辅助文字 |
| `--line` | `#DCE7ED` | 边框和分隔线 |
| `--ok` | `#168A70` | 成功状态 |
| `--warn` | `#B97916` | 待处理、预警状态 |
| `--danger` | `#C65353` | 风险、失败状态 |

禁止使用紫色渐变、荧光渐变、大面积纯蓝发光和与品牌无关的高饱和装饰色。

## 3. 页面结构

- 登录页：左侧 42% 品牌叙事区，右侧 58% 登录区；账号、密码、图形验证码，不显示角色选择，不传 `loginType`。
- 后台页：250px 深海蓝导航 + 顶部工作栏 + 冷米白内容区。
- 内容页：页面标题区 → 指标/提示 → 主内容卡片；列表页优先使用表格和状态标签。
- IP 新增页：分组表单、顶部接口提示、底部固定操作区。

## 4. 组件规范

- 卡片：白底、`1px` 浅蓝灰边框、轻阴影；圆角控制在 `0–4px`。
- 按钮：主按钮海湾蓝，次按钮白底细边框；不使用胶囊形大圆角。
- 按钮尺寸采用紧凑后台风格：普通按钮约 `34px` 高；橙色仅作为重点 CTA、提醒和待处理状态的辅助色，不替代蓝色主按钮。
- 输入框：高度 `40–46px`；聚焦时蓝色边框加低透明度外环。
- 状态标签：矩形小标签，使用浅色底和深色文字，不只用颜色表达状态。
- 表格：表头浅蓝灰背景，行间细线，操作使用蓝色文字按钮。
- 间距：以 `8px` 为基础单位，页面内边距建议 `38–44px`，卡片间距 `16–20px`。
- 字体：中文标题使用系统衬线字体增强文化感；正文使用系统无衬线字体；编号、金额和验证码可使用等宽字体。

## 5. 接口绑定示例

新增 IP 的“主归属城市”必须调用：

```http
GET /api/v1/admin/orgs/options
```

前端只保留 `status=ACTIVE` 且 `orgType=CITY` 的组织，显示 `orgName（cityCode）`，提交组织 `id` 到 `mainCityOrgId`。不得手工输入组织 ID，也不得用地区名称代替组织 ID。

## 6. 原型交互示例

专业版原型已示范：统一登录、退出、后台首页、IP 管理、IP 暂停/下架入口、新增 IP 表单、城市组织下拉、字典接口提示和操作反馈。所有“演示”动作均明确对应真实 API，前端 AI 接入时以 OpenAPI 为准替换 Mock 数据。

## 7. 角色菜单与精致交互基线

- 登录页只填写账号、密码、验证码，不提供角色选择；登录后调用 `/auth/me`，按返回角色渲染菜单。原型中的演示账号按钮仅用于预览不同角色，不是正式角色控件。
- 平台管理员：账号与组织、IP 管理、授权方案管理、平台配置；城市运营方：城市 IP 管理；版权/合规人员：IP 合规审核。
- 创作者：创作者工作台、IP 商城；我的授权、我的作品、商品管理、活动管理、订单与收益先以“待开发”状态展示。集团管理、财务、履约角色同样只展示其职责菜单，未完成接口不得伪装成可用功能。
- 危险操作使用二次确认弹窗，并要求填写原因；弹窗必须展示接口路径、取消/确认按钮和字段校验反馈。按钮需具备主次、悬停、按下、禁用状态。
- 原型必须能直接走通参考路径：平台管理员可进入“IP 管理→新增 IP”“账号与组织→添加组织”“授权方案管理→新增授权方案”；创作者可进入“注册/实名认证”；城市运营方可进入“城市 IP 管理→新增 IP”。登录后右上角提供“原型预览角色”切换，仅用于设计验收，真实产品仍通过 `/auth/me` 决定角色。
