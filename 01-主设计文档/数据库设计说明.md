# 星衍树版权二创平台一期 MVP 数据库设计说明

版本：v0.4  
数据库：MySQL 8.0+（InnoDB，`utf8mb4`，统一时区 `Asia/Hong_Kong`）  
依据：[一期MVP需求基线与范围说明.md](一期MVP需求基线与范围说明.md)、[业务状态机与流转规则.md](业务状态机与流转规则.md)、[页面功能与字段清单.md](页面功能与字段清单.md)

## 1. 设计目标与原则

本设计支撑一期主闭环：IP 入库确权 → 固定授权方案绑定 → 创作者实名购买授权 → 合同与素材 → 作品确权 → 商品/活动自动发布 → 消费者购买/预约 → 履约/核销/售后退款 → 分账结算 → 真实存证与审计。

1. **内部主键与业务编号分离。** 所有表使用 `BIGINT UNSIGNED` 内部主键；对外展示使用不可修改的业务编号，如 `IP-年月-流水号`、`AUTH-年月-流水号`、`ORD-年月-流水号`。
2. **状态由服务端控制。** 每个核心对象保存主状态、状态原因、最近状态变更信息；完整轨迹写入 `biz_status_history` 和 `sys_audit_log`。
3. **交易和发布必须快照化。** 合同、授权范围、商品/SKU、活动场次票种、售后模板、价格、分账规则及退款规则在关键节点保存 JSON 快照与版本号，历史记录不回读可变配置。
4. **固定方案不可覆写历史。** 授权方案、分账方案、售后/退款模板采用“主表 + 版本表”。已绑定 IP 的授权方案不得修改、停用、删除；规则变更新建方案或版本。
5. **隐私最小化。** 身份证号、统一社会信用代码、收款账户、地址、合同和权利文件都按字段或文件权限脱敏；密码只保存哈希；外部服务密钥只保存加密密文。
6. **外部调用可追踪。** 实名、短信、敏感内容、物流、文件存储和链上存证均保存请求号、结果、状态、重试和脱敏错误信息。
7. **并发校验在数据库层兜底。** 授权名额、SKU 库存、活动票种名额使用条件更新/锁定记录和唯一索引；支付回调、核销、退款、上链必须具备幂等键。
8. **不建立物理外键。** 所有 `*_id` 仅为逻辑关联字段，不创建 MySQL `FOREIGN KEY` 约束；关系存在性、删除限制、状态前置条件和跨表一致性由 Go 服务层在事务内校验和维护。

## 2. 命名、公共字段与数据类型

### 2.1 命名规范

- 表名采用小写蛇形命名，按领域前缀划分：`sys_`、`creator_`、`ip_`、`auth_`、`work_`、`product_`、`activity_`、`order_`、`after_sale_`、`finance_`、`evidence_`。
- 枚举字段使用 `VARCHAR(40)`，由枚举字典校验，不使用 MySQL `ENUM`，便于版本升级和 API 对齐。
- 字段字典中的“逻辑关联 `xxx.id`”仅用于说明关联目标，不对应数据库外键 DDL。
- 金额使用 `DECIMAL(18,2)`，比例使用 `DECIMAL(9,6)`（例如 `0.250000`），时间使用 `DATETIME(3)`。
- 常规文本使用 `VARCHAR`；介绍、意见、规则正文和快照使用 `TEXT`/`JSON`；文件只存文件对象 ID 和元数据，不存二进制。

### 2.2 核心表公共字段

除纯关系表和日志表外，核心业务表默认包含：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `BIGINT UNSIGNED` | 内部主键 |
| `status` | `VARCHAR(40)` | 当前主状态，使用状态机字典 |
| `status_reason_code` | `VARCHAR(64)` | 超时、检测失败、资料不足等原因码 |
| `status_reason` | `VARCHAR(500)` | 面向业务角色的脱敏原因说明 |
| `version` | `INT UNSIGNED` | 乐观锁版本，每次更新递增 |
| `created_by` / `updated_by` | `BIGINT UNSIGNED` | 操作用户；系统操作使用系统账号 |
| `created_at` / `updated_at` | `DATETIME(3)` | 创建和最后更新时间 |
| `status_changed_at` | `DATETIME(3)` | 最后状态变更时间 |
| `status_changed_by_type` | `VARCHAR(20)` | `USER`、`SYSTEM`、`THIRD_PARTY` |
| `status_changed_by_id` | `VARCHAR(64)` | 用户 ID、任务 ID 或外部服务标识 |

`deleted_at` 只允许用于可恢复的配置/标签类数据。合同、订单、实名、结算、审计、存证及所有历史业务表一期不允许逻辑或物理删除。

## 4. 核心实体设计

### 4.1 组织、用户和实名

| 表 | 主键/唯一约束 | 关键字段与说明 |
| --- | --- | --- |
| `sys_org` | `id`，`org_code` 唯一 | 组织类型（集团/平台/城市）、上级组织、城市编码、状态 |
| `sys_user` | `id`，`username` 唯一，`mobile` 唯一 | 后台用户账号、密码哈希、组织、数据范围、状态、最后登录时间；一期每个账号仅一个角色 |
| `sys_role` | `id`，`role_code` 唯一 | 7 个后台预置角色及权限范围 |
| `sys_user_role` | `(user_id, role_id)` 唯一 | 用户与角色关系，主角色标识 |
| `creator_profile` | `user_id` 唯一 | 主体类型、显示名/品牌名、实名状态、收款核验状态 |
| `creator_identity_verification` | `verification_no` 唯一 | 第三方实名请求与回执；身份号/信用代码加密存储和哈希去重 |
| `creator_authorization_letter` | `(creator_id, version_no)` 唯一 | 企业/工作室授权委托书资料留存；`FILED` 不影响实名认证或购买资格 |
| `consumer_account` | `mobile_hash` 唯一 | 消费者手机号密文/哈希/脱敏值、状态、最后登录时间、协议同意版本与时间；不与 `sys_user` 共用账号 |
| `consumer_address` | `id` | 消费者收货地址（含可选 `postal_code`）；订单创建时复制为完整订单快照，删除地址不影响历史订单 |
| `sms_code_log` | `id` | 注册/登录验证码发送、校验和频率控制记录 |

个人创作者身份证哈希、企业/工作室统一社会信用代码哈希分别建立唯一索引；原文仅保存加密字段。企业/工作室委托书仅作资料留存，不设平台确认流程；主体核验完全以第三方实名结果为准。

### 4.2 IP、权利与方案

| 表 | 主键/唯一约束 | 关键字段与说明 |
| --- | --- | --- |
| `ip_asset` | `ip_no` 唯一 | 名称、类型、主归属城市、一句话简介、完整介绍、文化故事、IP 特色、可创作方向、适用商品/活动类型、四类标签代码、公开版权说明、购买须知、主状态、DCI 证书状态/编号/文件/核验信息、授权方式、商城可见性 |
| `ip_right_holder` | `ip_id` 唯一 | 一个 IP 唯一的原始权利人；名称、类型、取得方式、权属说明 |
| `ip_right_document` | `(ip_id, document_no)` 唯一 | 版权证明类型、编号、有效期、文件 ID、状态 |
| `ip_dci_assistance_request` | `request_no` 唯一 | DCI 代办联系请求；联系人和手机号加密值/脱敏值、方便联系时间、处理状态、处理人和处理记录 |
| `ip_evaluation_report` | `report_no` 唯一 | 评估机构、日期、有效期、报告文件、可选评估建议价格 |
| `ip_review_record` | `id` | 城市运营提交、版权/合规审核、退回补充、确权结论轨迹 |
| `auth_plan` | `plan_no` 唯一 | 固定授权方案主实体，当前版本、绑定标识、状态 |
| `auth_plan_version` | `(plan_id, version_no)` 唯一 | 授权方式、期限、地区、场景、内容类型、名额、权限和权利方案快照；不保存 IP 交易价格 |
| `finance_distribution_plan` | `distribution_no` 唯一 | 普通分账/买断费用分配规则主实体 |
| `finance_distribution_plan_item` | `(distribution_plan_version_id, participant_type)` 唯一 | 参与方、比例、排序；比例合计 100% |
| `ip_auth_binding` | `ip_id` 唯一 | IP 与一个当前授权方案版本、一个分配方案版本的绑定及确认记录 |

`auth_plan.is_bound` 由 `ip_auth_binding` 维护。任一 IP 绑定后，方案及其历史版本禁止修改、停用、删除。IP 的 `main_city_org_id` 在确权后不得直接改动。IP 的 `suggested_transaction_price_amount` 独立存储在 `ip_asset`，评估报告的 `evaluation_suggested_price_amount` 存储在 `ip_evaluation_report`。

价格口径：`evaluation_suggested_price_amount` 为评估报告中的非必填参考价格；`suggested_transaction_price_amount` 为 IP 建议交易价，IP 确权确认时锁定，商城展示和授权下单使用该价格。授权订单的 `amount` 与 `purchase_snapshot` 必须保存下单时价格。

`ip_asset.dci_certificate_status` 独立于 IP 主状态，取值为 `MISSING`、`ASSISTANCE_REQUESTED`、`UPLOADED`、`VERIFIED`、`REJECTED`。不设置物理外键；IP 与 DCI 代办请求、证书文件和处理人关系均由服务层校验并保留审计记录。

IP 的地域、文化、品类和商业化标签分别以 `*_tag_codes_json` 保存受控标签编码数组，标签主数据复用 `sys_dict_item`；服务层负责校验编码存在、类型匹配且已启用。IP 类型、授权方式、售后类型、DCI 状态等固定枚举也存放在该表，由 `bootstrap` 按“字典类型 + 编码”幂等补齐，只读使用；地区和四类标签则由平台管理员在 A05 的“地区管理”“标签管理”选项卡维护。可创作方向、适用商品类型和适用文旅活动类型作为 IP 商城展示与创作者创作提示数据，不替代授权方案中的实际授权边界。

### 4.3 授权订单、合同和素材

| 表 | 主键/唯一约束 | 关键字段与说明 |
| --- | --- | --- |
| `auth_order` | `auth_order_no` 唯一；支付幂等键唯一 | 创作者、IP、方案版本、金额、待支付截止时间、订单状态、购买快照 |
| `creator_authorization` | `authorization_no` 唯一 | 生效授权、有效期、状态、合同和范围快照引用、买断标识 |
| `auth_contract` | `contract_no` 唯一；`authorization_id` 唯一 | 虚拟合同文件、双方主体快照、合同生效时间、Hash、存证状态 |
| `auth_certificate` | `certificate_no` 唯一 | 授权凭证文件、授权范围摘要、Hash、存证状态 |
| `auth_scope_snapshot` | `authorization_id` 唯一 | IP、方案、地区、场景、期限、内容类型、分账说明 JSON 快照 |
| `ip_material_pack` | `ip_id` 唯一；冻结后禁止更新 | 入库素材包主记录、清单 Hash、存证状态/回执、冻结状态与时间；确权上架后固定为 `FROZEN`，不采用原 IP 内版本覆盖 |
| `ip_material_pack_item` | `(material_pack_id, item_no)` 唯一 | 素材项、文件 ID、原始文件名、MIME 类型、大小、文件 SHA-256、素材角色、排序、可交付标识与适用授权范围；冻结后禁止更新 |
| `material_download_log` | `id` | 授权、合同、素材包、下载人、IP、下载时间、结果 |

素材包清单 Hash 由按稳定规则排序的素材项和文件 SHA-256 生成；链上仅存证文件 Hash、清单 Hash、可选 Merkle Root 及回执，不上传素材二进制本体。DCI 代办请求应关联创建时锁定的素材包清单 Hash；需要补正时新建请求，不能改写已锁定提交包。`ip_material_pack` 在 IP 确权、关键材料和素材包存证均成功时置为 `FROZEN`；此后原 IP、素材包及素材项禁止更新、删除、替换或追加，新增/修正素材必须新建 IP 记录。

授权订单支付成功后创建 `creator_authorization`、合同、凭证和范围快照。合同/凭证/授权范围快照需引用冻结素材包的清单 Hash。并发约束是“同一创作者、同一 IP 同时仅一笔 `ACTIVE` 授权”；自然到期后可以按届时有效的新方案创建新订单和新授权，不属于自动续期。独家买断成功后 IP 商城可见性关闭。

### 4.5 订单、支付、物流和核销

| 表 | 主键/唯一约束 | 关键字段与说明 |

| `product_order` | `order_no` 唯一 | 消费者、订单状态、完整收货地址快照、金额、运费、30 分钟支付截止、履约/售后状态；H5-02 支持跨创作者/商品合单且统一平台履约 |

| `product_stock_reservation` | `reservation_no` 唯一 | SKU、订单项、预占数量、过期时间、`RESERVED/CONSUMED/RELEASED` 状态；取消/超时释放，支付成功转正式消耗 |
| `activity_booking` | `booking_no` 唯一 | 消费者、活动/场次/票种、数量、金额、预约状态、规则快照；免费票直接待核销，收费票待支付后转待核销 |
| `activity_quota_reservation` | `reservation_no` 唯一 | 票种、预约单、预占数量、过期时间、`RESERVED/CONSUMED/RELEASED`；仅收费票待支付占用 |
| `payment_transaction` | `payment_no` 唯一；`idempotency_key` 唯一 | 订单类型/编号、模拟支付、支付状态、外部/模拟流水号、金额 |
| `delivery_order` | `delivery_no` 唯一；`order_id` 唯一 | 发货主体、物流公司、运单号、发货/签收时间、凭证 |
| `logistics_event` | `(delivery_id, event_no)` 唯一 | 物流轨迹、事件时间、状态、原始回调摘要 |
| `verification_code` | `code_hash` 唯一；`booking_id` 唯一 | 预约电子核销码、至场次结束有效、状态、使用时间；活动结束未核销转过期 |
| `verification_record` | `booking_id` 唯一 | 核销人员、核销点、时间、结果、异常、现场凭证 |

商品、活动和授权订单均为待支付 30 分钟关闭；相应的库存、名额或授权名额在关闭时原子释放。支付、物流、核销回调按幂等键和状态条件更新，重复回调不得重复扣减、完成或分账。

## 5. 关键完整性约束与索引

固定售后模板采用追加版本方式：`after_sale_rule_template` 的唯一约束为 `(template_no, version_no)`。平台创建新版本时停用旧版本；商品、活动和订单保留关联模板 ID 与规则快照，因此历史交易不会因新版本发生变化。

### 5.1 必须建立的唯一约束

| 业务规则 | 建议约束 |
| --- | --- |
| 后台账号、消费者手机号唯一 | `sys_user.username`、`sys_user.mobile`、`consumer_account.mobile` 唯一 |
| 个人/企业创作者实名唯一 | 身份号哈希、统一社会信用代码哈希唯一（分主体类型） |
| 一个 IP 一个原始权利人 | `ip_right_holder.ip_id` 唯一 |
| 一个 IP 一个当前授权方案绑定 | `ip_auth_binding.ip_id` 唯一 |
| 方案版本、商品版本、活动版本、作品版本有序唯一 | 各对象 ID + `version_no` 唯一 |
| 业务编号不可重复 | 各 `*_no` 字段唯一 |
| 同一有效授权期间不得重复购买同一 IP | 在 `creator_authorization` 上通过 `creator_id + ip_id + active_flag` 唯一索引实现；`active_flag` 仅在 `ACTIVE` 为 1，到期/解除为 NULL |
| 支付/退款/核销幂等 | 支付幂等键、退款业务键、预约核销记录唯一 |
| 商品订单项、活动票种、分账参与方不重复 | 对应复合唯一索引 |

MySQL 不支持直接使用“状态 = ACTIVE”的部分唯一索引，建议维护一个可空生成列或应用维护列 `active_flag`：有效授权值为 `1`，失效/解除值为 `NULL`，并建立 `(creator_id, ip_id, active_flag)` 唯一索引。这样同一创作者可在旧授权到期后重新购买，但不能同时持有两笔有效授权。

### 5.2 逻辑关联校验（Go 服务层）

数据库不创建物理外键。所有以下校验必须由服务层在同一事务中完成，发生逻辑删除、状态改变或数据迁移时也由服务层保证一致性：

| 场景 | 服务层必须校验 |
| --- | --- |
| 创建/提交 IP | 城市组织存在且可用；授权方案和分配方案为可选用的有效版本 |
| 创建授权订单 | 创作者实名、IP 状态、方案绑定、名额和当前有效授权均满足要求 |
| 提交作品/商品/活动 | 创作者、IP、授权、作品、方案与状态存在且在同一授权边界内 |
| 创建订单/预约 | 商品/SKU 或活动/场次/票种存在、已发布且库存/名额足够 |
| 支付、退款和核销 | 原订单、售后、预占、支付流水和当前状态匹配；幂等键未被错误复用 |
| 分账与结算 | 来源订单、授权模式、分账参与方、收款账户与冻结状态匹配 |
| 文件、存证和日志 | 关联对象存在；文件访问权限、对象版本和 Hash 一致 |

服务层不得依赖数据库外键报错替代业务校验。所有逻辑关联 ID 仍需建立面向查询的普通索引，避免无外键情况下出现全表扫描。

## 6. 事务、锁与异步任务

### 6.1 必须使用数据库事务的场景

1. **创建待支付授权订单：** 校验实名、IP 上架、方案有效、名额剩余、有效授权唯一性，锁定名额，创建订单和快照。
2. **商品/活动待支付创建：** 校验发布状态、SKU/票种库存或名额，创建预占记录和订单/预约快照。
3. **支付成功：** 以支付幂等键更新交易，预占转正式占用，更新订单；授权支付还要创建授权、合同、凭证和范围快照。
4. **退款成功：** 更新退款单、售后单、订单/预约状态，恢复库存/名额（适用时），创建冲销记录并冻结/更新分账。
5. **核销成功：** 条件更新核销码，写核销记录，完成预约订单，生成分账任务。
6. **结算完成：** 更新结算批次、结算项、分账项付款状态和付款凭证关联。

### 6.2 定时/异步任务

| 任务 | 扫描条件 | 操作 |
| --- | --- | --- |
| 待支付关闭 | 订单待支付且 `payment_expire_at < now()` | 条件关闭订单，释放库存/名额/授权名额 |
| 授权到期 | 授权 `ACTIVE` 且 `end_at <= now()` | 改为到期，关闭素材新下载和内容新建能力 |
| 活动结束 | 活动最后场次结束 | 停止预约，未核销预约改为已过期 |
| 商品自动完成 | 已签收且售后保护期届满且无售后 | 订单完成，创建分账任务 |
| 检测补偿 | 检测中超时或失败可重试 | 写异常或重试记录，默认阻断流转 |
| 存证补偿 | `FAILED`/待上链的证据记录 | 按策略重试，保存回执和失败原因 |
| 分账计算 | 已完成商品订单/已核销预约 | 计算普通授权分账或标记买断创作者自有收入 |

## 7. 快照、文件与数据留存

### 7.1 必须保存的快照

| 触发点 | 快照内容 |
| --- | --- |
| IP 确权 | 权利人、主城市、权利证明、授权/分账方案、商城展示内容 |
| 授权下单 | 创作者主体、IP、方案版本、价格、期限、地区、场景、内容类型、合同条款 |
| 授权生效 | 合同正文、授权凭证、完整授权边界、方案和分配规则 |
| 作品提交/确权 | 作品文本、声明、关联授权、文件 Hash、审核结论 |
| 商品/活动发布 | 内容版本、自动校验结果、授权边界、售后/退款模板 |
| 商品下单/活动预约 | 商品/SKU或活动/场次/票种、价格、运费、地区、规则、消费者确认 |
| 售后/退款 | 订单、地址、规则、凭证、退款金额、审核结论 |
| 分账/结算 | 分账基数、比例、参与方、冲销、收款主体、付款凭证 |

### 7.2 文件与脱敏

文件对象通过 `file_object` + `file_relation` 管理，业务表只引用 `file_id`。下载由短期签名 URL 完成，下载动作写审计。身份证明、版权证明、评估报告、授权委托书、合同、作品源文件、收款账户与收货地址均属于敏感数据；消费者只能读取商品/活动公开图片和通俗版权说明。

订单、合同、实名、结算和存证数据长期留存。用户不支持一期内注销或删除历史业务数据。
