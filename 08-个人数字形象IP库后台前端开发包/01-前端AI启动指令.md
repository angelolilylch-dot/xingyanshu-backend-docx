# 后台前端 AI 启动指令

开发“个人数字形象 IP 库”后台模块，按当前后台管理员 token 与菜单权限渲染，不修改消费者 H5 和独立 AVATAR_H5。

一级菜单固定为“个人数字形象管理”，由 `GET /api/v1/auth/me` 返回的 `MENU_AVATAR_MANAGEMENT` 控制显示。前端路由根路径为 `/avatar-management`：城市运营者默认进入 `/avatar-management/rosters`，平台管理员默认进入 `/avatar-management/quality-reviews`；无对应操作权限的子路由不显示且不可手工访问。

角色与菜单：

| 角色 | 所需权限 | 页面 |
| --- | --- | --- |
| 城市运营者 | `AVATAR_ROSTER_MANAGE` | 名单模板、导入、批次、错误回执、手动执行本批次实名核验 |
| 城市运营者 | `AVATAR_REGISTRATION_ENTRY_MANAGE` | 固定二维码查看、PNG 下载、显式更换、暂停/恢复；固定客服电话由后端配置维护 |
| 城市运营者 | `AVATAR_PROGRESS_VIEW` | 名单与档案进度 |
| 城市运营者 | `AVATAR_INVITATION_NOTIFY` | 建档提醒短信 |
| 城市运营者 | `AVATAR_PROGRESS_EXPORT` | 去标识化进度导出 |
| 平台管理员 | `AVATAR_QUALITY_REVIEW` | 人工质检、一次性素材预览、审核决定 |
| 平台管理员 | `AVATAR_ARCHIVE_EXPORT` | 原始归档包导出、一次性密码、重生成 |

统一处理后端响应 `code/message/data/requestId/timestamp`。所有 ID 按字符串处理。写操作须二次确认、禁用重复点击并带 `Idempotency-Key`；当前 Avatar 后端尚未实际执行幂等去重，前端不可假设安全重试。

严禁：在列表解密姓名/手机号；在页面显示完整身份证号；缓存一次性预览令牌、下载链接或归档密码；把管理后台接口放入 H5；绕过城市数据范围做前端筛选。

批次状态为 `PENDING_IDENTITY` 时显示“立即执行实名核验”按钮，二次确认后调用 `POST /api/v1/avatar/roster-batches/{id}/identity-verifications/run`；请求中禁用按钮，成功后提示 `data.processedCount` 并刷新批次详情。仅 `PENDING_IDENTITY` 显示按钮；再次点击只处理仍待核验人员，`processedCount=0` 时提示“该批次没有待核验名单”。

建档入口页面加载即调用 `GET /api/v1/avatar/registration-qrcodes`：有 `canDownload=true` 的当前二维码时直接使用 `registrationURL` 展示，并将 `downloadPath` 作为图片下载链接；不得再次调用创建接口。仅不存在当前二维码时显示“创建二维码”。“更换二维码”必须二次确认，调用 `POST /api/v1/avatar/registration-qrcodes/{id}/rotate` 后刷新列表；旧二维码会立即失效。历史记录的 `canDownload=false` 不可下载，提示运营者显式更换。
