# 后台 Mock 联调与验收

## 环境边界

- 后台所有接口使用既有管理员登录态，不使用 `AVATAR_H5` token。
- Mock 短信、实名、自动质检仅在后端 `test` 环境有效。生产环境不得由前端伪造成功状态。
- 当前名单导入接口的真实表头固定为：`姓名`、`手机号`、`性别`。请始终优先下载 `GET /avatar/rosters/template` 返回的模板。
- `个人数字形象名单导入模板.xlsx` 是“目标四列模板”设计稿，待后端实现身份证号与导入前实名 Mock 后才能上传；它不是当前接口可上传文件。

## 必测场景

| 页面 | 必测结果 |
| --- | --- |
| 名单导入 | xlsx 以外格式拒绝；表头错误收到 `AVATAR_ROSTER_HEADER_INVALID`；单行失败不影响同批有效行；可下载错误回执。 |
| 二维码与提醒 | 暂停二维码后 H5 入口不可用；提醒短信限频由服务端判定；前端不把 Mock 成功当生产能力。 |
| 城市进度与导出 | 城市端只见本城市脱敏数据；只可创建 `PROGRESS_LIST`。 |
| 人工质检 | 预览令牌仅一次、5 分钟有效；决定请求带 `version`；非通过必须填写原因。 |
| 删除与归档包 | 城市端不能访问；密码只显示一次，关闭后只允许重生成，不能从本地恢复。 |

## 前端统一处理

- 写操作二次确认、禁用重复点击并携带 `Idempotency-Key`；当前服务端尚未据此去重，前端不可自动重试。
- 所有 ID 作为字符串，统一先检查响应外层 `code`；显示 `message` 与 `requestId`，不得向普通用户暴露内部详情。
- 下载、预览、密码均不得写入 localStorage、URL、长期状态或日志。
