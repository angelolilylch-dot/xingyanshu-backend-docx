# 页面业务逻辑与接口清单

## 一、城市运营后台

前端子路由：`/avatar-management/rosters`、`/avatar-management/entry`、`/avatar-management/profiles`、`/avatar-management/exports`。

| 页面 | 业务逻辑 | 实际接口 |
| --- | --- | --- |
| 名单导入 | 先下载模板，再上传 `.xlsx`；固定列为姓名、身份证号、手机号、性别。导入后显示 `PENDING_IDENTITY`，轮询批次直到实名核验完成；成功名单才可建档，失败下载错误回执。身份证号仅在上传时提交，前端不得展示、缓存、记录日志或导出。 | `GET /avatar/rosters/template`；`POST /avatar/roster-batches/import`；`GET /avatar/roster-batches`；`GET /avatar/roster-batches/{id}`；`GET /avatar/roster-batches/{id}/errors` |
| 名单及建档进度 | 仅显示脱敏姓名、脱敏手机号、性别、注册状态、档案编号/状态；不显示实名结果、身份证号或素材。 | `GET /avatar/roster-members`；`GET /avatar/profiles` |
| 城市建档入口 | 保存城市联系人和电话；创建二维码后以前端二维码组件渲染返回的短码/注册路径；支持暂停、恢复。 | `PUT /avatar/city-registration-config`；`POST/GET /avatar/registration-qrcodes`；`POST /avatar/registration-qrcodes/{id}/pause`；`POST /avatar/registration-qrcodes/{id}/resume` |
| 建档提醒 | 仅对待建档人员显示发送按钮；24 小时限发由服务端判断。测试环境可成功，其他环境服务端可能拒绝。 | `POST /avatar/roster-members/{id}/sms-notifications` |
| 进度导出 | 创建 `exportType=PROGRESS_LIST`，轮询详情，成功后按服务端返回的单次下载动作处理。 | `POST /avatar/exports`；`GET /avatar/exports`；`GET /avatar/exports/{id}`；`POST /avatar/exports/{id}/download` |

## 二、平台管理员后台

前端子路由：`/avatar-management/quality-reviews`、`/avatar-management/deletion-requests`、`/avatar-management/archive-exports`。

| 页面 | 业务逻辑 | 实际接口 |
| --- | --- | --- |
| 人工质检待办 | 显示待办；可将已提交采集会话加入抽检/风险复核。 | `GET /avatar/quality-reviews/pending`；`POST /avatar/collection-sessions/{id}/quality-reviews` |
| 受控预览 | 先申请素材级一次性预览令牌，再立即加载预览流；令牌 5 分钟、单次有效，不写本地缓存。 | `POST /avatar/quality-reviews/{id}/previews`；`GET /avatar/quality-previews/{token}` |
| 质检决定 | `PASSED`、`REJECTED`、`RESHOOT_REQUIRED`；非通过必须填写原因码和说明，并带当前 `version`。 | `POST /avatar/quality-reviews/{id}/decision` |
| 删除审批 | 列表查看申请，决定删除、拒绝或法定保留；法定保留必须填写对应码和理由。 | `GET /avatar/deletion-requests`；`POST /avatar/deletion-requests/{id}/decision` |
| 原始归档包 | 仅平台管理员创建 `exportType=ARCHIVE_PACKAGE`，必须填写 `purposeCode`；成功后下载、密码仅展示一次；丢失后重生成。 | `POST /avatar/exports`；`GET /avatar/exports`；`GET /avatar/exports/{id}`；`POST /avatar/exports/{id}/download`；`POST /avatar/exports/{id}/password/reveal`；`POST /avatar/exports/{id}/regenerate` |

## 三、关键请求字段

| 接口 | 请求体 |
| --- | --- |
| 城市联系人 | `{supportContactName, supportContactPhone}` |
| 发送提醒 | `{templateCode?}` |
| 加入人工复核 | `{reviewType:"SAMPLE"|"RISK", reasonCode, reason?}` |
| 质检决定 | `{version, decision:"PASSED"|"REJECTED"|"RESHOOT_REQUIRED", reasonCode?, reason?}` |
| 导出 | `{exportType:"PROGRESS_LIST"|"ARCHIVE_PACKAGE", cityOrgId?, purposeCode?, profileIds?}` |
| 删除审批 | `{decision, retentionExceptionCode?, reason}` |

## 四、前端状态与安全规则

- 导入失败不是整批失败：展示批次统计，并下载服务器生成的错误回执。
- 城市运营者永远只能读取本城市的脱敏进度；平台人工质检与原始归档包不能赋予城市运营者。
- 质检预览不是文件下载：预览令牌必须当次使用，禁止保存在 URL、日志、状态管理持久化或截图说明中。
- 归档包密码只能显示一次。关闭提示框后不可从前端恢复，必须走后端重生成。
- 名单实名核验为批处理：服务端加密入库后由 Worker 解密并调用服务；当前 `test` 环境使用 Mock，生产必须配置真实实名服务。后台前端只能展示批次和核验结果，不能显示身份证号。
