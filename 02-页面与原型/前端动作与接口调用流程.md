# 前端动作与接口调用流程（已实现接口）

> 适用版本：v0.5 授权交易与后续业务。更新日期：2026-09-28。
>
> 本文件只记录后端已经实现、可联调的前端动作。授权订单、测试 Mock 支付、授权合同/凭证/素材下载、二创作品闭环及商品二级审核闭环已实现；活动、消费者 H5、履约、售后、财务和运营接口仍不得据此虚构页面、按钮或调用链。

## 1. 通用动作约定

1. 管理后台与创作者登录成功后，先调用 `GET /api/v1/auth/me`；以返回的主体、角色、权限、`menus[]` 和创作者实名状态决定菜单、引导与可执行动作，不能以原型角色下拉框决定权限。创作者页面及版权/合规审核动作必须由服务端菜单和权限控制；不得把原型中尚无服务端菜单支持的商品、活动、消费者 H5、履约、财务或看板入口作为可联调功能渲染。
2. 所有写操作在用户确认后才发送；接口要求幂等时由请求封装生成并携带 `Idempotency-Key`。编辑、审核、启停等有版本的操作必须携带 `If-Match-Version`。
3. 成功后以接口返回的数据更新当前页，或重新请求详情/列表；`VERSION_CONFLICT`、`STATE_TRANSITION_NOT_ALLOWED`、`IDEMPOTENCY_CONFLICT` 均保留用户已填表单并提示刷新。
4. 文件先走 `POST /api/v1/files`（创作者私有文件使用 `POST /api/v1/creator/files`），成功后仅保存并提交 `fileId`；下载只能调用签发短期地址的下载接口。

## 2. A：平台管理员与通用后台

### A01 登录、会话与密码

```text
进入登录页 → GET /auth/captcha → 输入账号、密码、验证码
→ POST /auth/login → 保存 Token → GET /auth/me → 按角色进入首页
```

- 刷新会话（后台与创作者共用，消费者 H5 不在本次范围）：受保护请求首次收到 `401 AUTH_TOKEN_EXPIRED` 时，拦截器以当前最新 `refreshToken` 发起一次 `POST /auth/refresh`，请求体为 `{ "refreshToken": "..." }`，不携带 `Authorization`。同一时刻只允许一个刷新请求，其余失败请求等待结果。
- 刷新成功：先原子覆盖内存中的 `accessToken` 和 `refreshToken`，再使用新 accessToken 重放全部等待中的原请求；不得继续使用旧 refreshToken，也不得在替换前调用 `/auth/me`。
- 刷新失败或重放后再次 `401`：清除本地会话并跳转登录页；不得对 `/auth/refresh` 自身递归刷新。
- 退出：点击退出 → `POST /auth/logout` → 清除本地会话 → 登录页。
- 修改密码：已登录页填写旧/新密码 → `POST /auth/password/change` → 成功后按服务端会话规则重新登录。
- 找回密码：发短信 `POST /auth/password-reset/sms/send` → 填验证码与新密码 → `POST /auth/password-reset`。

### A02 账号管理

```text
进入列表 → GET /admin/accounts
→ 新增/编辑/启停/重置密码 → 成功后刷新列表或详情
```

- 新增：打开组织、角色等下拉（需要时先取 `GET /admin/orgs/options`）→ 确认 → `POST /admin/accounts`。
- 查看：点击行 → `GET /admin/accounts/{userId}`。
- 编辑：详情加载后编辑 → `PATCH /admin/accounts/{userId}`，带版本号。
- 启停：二次确认并填写原因 → `PATCH /admin/accounts/{userId}/status`，带版本号；停用当前会话时立即退回登录页。
- 重置密码：二次确认 → `POST /admin/accounts/{userId}/password/reset`；只提示管理员线下通知，绝不在前端展示密码。

### A03 组织管理

```text
进入列表 → GET /admin/orgs
→ 查看/新增/编辑/启停 → 刷新当前记录
```

- 新增：填写组织资料 → `POST /admin/orgs`。
- 编辑：`GET /admin/orgs/{orgId}` → `PATCH /admin/orgs/{orgId}`，带版本号。
- 启停：说明原因并确认 → `PATCH /admin/orgs/{orgId}/status`，带版本号。
- 下拉选择组织时只调用 `GET /admin/orgs/options`，提交 `id`，不提交城市名称。

### A04 平台基础资料与文件

- 字典：页面初始化或下拉展开时请求 `GET /dictionaries/{dictType}`；显示 `name`，提交 `code`。
- 标签：列表 `GET /admin/tags`；新增 `POST /admin/tags`；启停 `PATCH /admin/tags/{tagId}/status`。
- 地区：列表 `GET /admin/regions`；新增 `POST /admin/regions`；启停 `PATCH /admin/regions/{regionId}/status`。公开选择器使用 `GET /public/regions`。
- 系统参数：`GET /admin/configs` → 修改确认 → `PATCH /admin/configs/{configKey}`。
- 售后模板：`GET /admin/after-sale-templates` → 新增 `POST /admin/after-sale-templates`；新版本 `POST /admin/after-sale-templates/{templateId}/versions`；启停 `PATCH /admin/after-sale-templates/{templateId}/status`。
- 通用文件：上传 `POST /files`；查看 `GET /files/{fileId}`；用户明确下载后 `POST /files/{fileId}/download-url` 并使用返回的短期 URL。

## 3. B：城市 IP、版权合规与授权方案

### B02 城市 IP

```text
进入列表 → GET /ips
→ 新增或编辑 → 上传文件取得 fileId → POST/PATCH /ips
→ 提交审核 → POST /ips/{ipId}/submit → 刷新详情
```

- 新增 IP：打开主归属城市下拉时请求 `GET /admin/orgs/options`，仅选 `CITY/ACTIVE`；如选择 DCI 代办，在同一个 `POST /ips` 中提交 `dciAssistanceRequested` 及联系人资料，且禁用并清空 DCI 证书字段。
- 编辑：`GET /ips/{ipId}` 加载；仅允许 `DRAFT/SUPPLEMENT_REQUIRED`；`PATCH /ips/{ipId}` 带版本号。
- 已保存 IP 的 DCI 代办：`POST /ips/{ipId}/dci-assistance-requests`；不新增独立“保存草稿”动作。
- 提交：确认补充完成后 `POST /ips/{ipId}/submit`；成功进入待合规状态，刷新详情和列表。
- 评估报告：上传得到 `fileId` → `POST /ips/{ipId}/evaluation-reports`。

### B03 版权合规与确权

```text
进入待办 → GET /compliance/ips/pending
→ 查看 IP → GET /ips/{ipId}
→ DCI/代办处理/确权 → 成功后刷新待办与详情
```

- DCI 代办列表：`GET /compliance/dci-assistance-requests`；处理 `POST /compliance/dci-assistance-requests/{requestId}/handle`；下载资料包 `POST /compliance/dci-assistance-requests/{requestId}/application-package`。
- DCI 核验：确认结果和意见 → `POST /ips/{ipId}/dci-verifications`。
- 权属确权：确认方案、分配及结论 → `POST /ips/{ipId}/rights-reviews`。成功时显示 `status=LISTED`、`mallVisible=true`、`evidenceReceiptNo` 与可复制的 `evidenceTransactionHash`；不能把材料 SHA-256 摘要当作链上哈希。
- 商城状态：有权限且状态允许时，暂停 `POST /ips/{ipId}/pause`、恢复 `POST /ips/{ipId}/resume`、下架 `POST /ips/{ipId}/delist`；均需原因、二次确认和版本号。

### B04 授权方案与分账模板

```text
进入列表 → 分别 GET /auth-plans、GET /distribution-templates
→ 各自创建/编辑草稿 → 授权方案提交 → 合规审核 → 启用或停用
```

- 模板：详情 `GET /distribution-templates/{templateId}`；新增 `POST /distribution-templates`；编辑 `PATCH /distribution-templates/{templateId}`；启停 `PATCH /distribution-templates/{templateId}/status`。
- 授权方案：详情 `GET /auth-plans/{planId}`；新增 `POST /auth-plans`；草稿编辑 `PATCH /auth-plans/{planId}/draft`；提交、启用、停用分别调用 `POST /auth-plans/{planId}/submit|enable|disable`；合规审核调用 `POST /auth-plans/{planId}/reviews`。
- 新增或编辑授权方案时不提交、展示或校验 `distributionTemplateId`。城市运营在 B02 创建 IP、版权/合规在 B03 确权时，才从已启用模板中选择与授权方式同类型的模板，并填写该 IP 专属比例。
- 所有状态按钮由权限、详情状态和服务端返回结果共同控制；已绑定 IP 的方案不得在前端伪造修改或停用入口。

## 4. C：创作者（当前仅 C01、C02）

### C01 注册、实名与主体资料

```text
注册页 → POST /creator/auth/sms/send → POST /creator/auth/register
→ 保存 Token → GET /auth/me → 跳转“主体实名认证”引导
→ POST /creator/identity-verifications
→（企业/工作室成功时，响应含 Word 草稿短链）→ GET /auth/me/GET latest 刷新状态
```

1. 注册只提交 `mobile/password/smsCode/displayName`；成功后创作者档案为 `PERSONAL + UNVERIFIED`，不把注册字段与实名字段混成同一个请求。
2. 注册后推荐立即进入实名认证；用户也可进入 C02 浏览商城。首次登录不自动代替用户发起实名认证。
3. 实名表单提交 `subjectType`（`PERSONAL/ENTERPRISE/STUDIO`）、`legalName`、`credentialType`、`credentialNo`，调用 `POST /creator/identity-verifications`。测试环境 Mock 会直接返回 `VERIFIED`；生产前端仍按异步结果页的结构处理。
4. 成功后调用 `GET /creator/identity-verifications/latest` 和 `GET /auth/me` 刷新状态；证件号码仅写入，不回显完整值。
5. 企业/工作室成功响应中的 `authorizationLetterDraftFileId/fileName/downloadUrl/expiresAt` 对应一份服务端自动生成的私有 `.docx` 草稿。前端显示“下载委托书草稿”链接及有效期；链接过期或用户点击刷新时，调用 `GET /creator/authorization-letter-draft` 重新取得同一草稿的短期链接。不得将 URL 长期缓存，也不得把草稿当成已签署文件。
6. 用户补全受托人、期限、盖章、签字后，可选上传签署件：`POST /creator/files` → `POST /creator/authorization-letters`（`fileId`）。`FILED` 仅代表签署件资料留存，不是购买前置；标准纯文本模板接口 `GET /creator/authorization-letter-template` 仍可用于用户自行查看模板。

### C02 IP 商城与购买预览

```text
进入商城 → GET /creator/ip-mall
→ 修改筛选/分页 → 重新 GET /creator/ip-mall
→ 打开详情 → GET /creator/ip-mall/{ipId}
→ 点击购买预览 → GET /creator/ip-mall/{ipId}/purchase-preview
```

- 列表筛选使用 `keyword/regionCode/ipType/tagCodes/authorizationMode/contentType/term/minPrice/maxPrice/sortBy/pageNo/pageSize`；`tagCodes` 使用英文逗号分隔。
- 未实名可浏览卡片和详情；卡片 `canPurchase=false` 或购买预览 `canPurchase=false` 时，展示服务端 `blockCode/reasons`。
- 若原因为未实名，提示“完成实名认证后可购买”，提供“去实名认证”按钮跳到 C01；不自动调用实名接口。
- C02 详情页先调用 `GET /creator/ip-mall/{ipId}` 与 `GET /creator/ip-mall/{ipId}/purchase-preview`；后者 `canPurchase=false` 时仅展示后端原因，不进入购买确认。
- C03 购买确认页必须先勾选虚拟合同及购买须知，再以新的 `Idempotency-Key` 调用 `POST /creator/auth-orders`。成功后进入待支付页，展示订单号、金额和 `paymentExpireAt` 倒计时。
- 仅测试环境显示“模拟支付成功（仅测试环境）”，点击后以新的 `Idempotency-Key` 调用 `POST /payments/mock/pay`，请求 `{ "bizType": "AUTH_ORDER", "bizOrderId": "授权订单ID" }`。成功即表示支付完成且授权生效，直接进入购买记录；生产环境不得注册或显示此入口。
- 购买记录调用 `GET /creator/authorizations`，详情调用 `GET /creator/authorizations/{authorizationId}`。合同或凭证 `downloadReady=false` 时展示生成中并刷新详情；为 `true` 后分别调用 `GET .../contract`、`GET .../certificate` 获取临时下载 URL。
- 存证状态独立于支付和授权：`PENDING_EVIDENCE`、`EVIDENCE_RETRYING` 展示处理中，`EVIDENCED` 展示回执号和交易哈希，`EVIDENCE_FAILED` 展示平台处理中，不重新支付。
- 创建返回 `AUTH_ORDER_PENDING_EXISTS` 时，跳转其返回的既有订单查看页；不得创建第二笔订单。订单页通过 `GET /creator/auth-orders/{authOrderId}` 刷新状态。
- 创作者可调用 `POST /creator/auth-orders/{authOrderId}/cancel` 取消仍有效的待支付订单。超时或取消后展示“订单已关闭”，不展示“重新下单”；只提供“返回 IP 详情”入口。
- `quotaTotal` 为空表示不限额，不创建预占；有值的普通授权及独家买断创建待支付订单时预占名额。前端不得自行计算名额，始终以创建/查询接口结果为准。

## 5. D：C05 二创作品提交、审核与确权

```text
我的作品 → GET /creator/works
→ 提交前查询本人有效授权及冻结素材包 → POST /creator/works
→ 文本检测结果 → 版权初审 → 合规复核 → 确权存证
→ GET /creator/works/{workId} 查看版本、审核和确权状态
```

- 创作者仅可使用本人 `ACTIVE` 且未到期、允许二创的授权。提交前调用 `GET /creator/authorizations/{authorizationId}/material-packs`，从返回的冻结且已存证素材包中选择 `materialItemIds`；不得自行传 IP ID，也不得直接传裸 `fileId` 代替素材项。
- 提交作品前先将预览、源文件和过程证据上传到 `POST /creator/files`，再以新的 `Idempotency-Key` 调用 `POST /creator/works`。必填内容包括授权、作品名称/类型、创作说明、五项声明、独创表达自评比例（51–100）、独创表达维度与说明、原始 IP 使用说明、预览文件、源文件及素材项。
- 提交返回 `PENDING_COPYRIGHT_REVIEW` 或其检测结果后刷新列表；`TEXT_REJECTED`、`TEXT_CHECK_ERROR`、`RETURNED`、`REJECTED` 只能通过 `POST /creator/works/{workId}/resubmit` 创建新版本，不得覆盖原版本。`RIGHTS_CONFIRMED` 的作品才可作为后续商品候选项。
- 版权/合规人员使用 `GET /copyright/works/pending` 取得待办。版权初审或合规复核均调用 `POST /copyright/work-versions/{workVersionId}/reviews`，提交 `reviewNode=COPYRIGHT_INITIAL|COMPLIANCE_REVIEW`、`result=PASS|RETURN|REJECT`、审核意见和退回项；合规复核通过后，调用 `POST /copyright/works/{workId}/rights-confirmations`，提交确认的新增独创表达比例。
- 确权响应与作品详情中的快照 Hash、存证状态和交易 Hash 仅用于展示与复制。`PENDING_EVIDENCE` 不应被显示为作品审核失败；创作者只就平台确认的新增独创表达主张权利，不取得原始 IP 权属。

## 6. E：C06 商品与 SKU 二级审核

```text
我的商品 → GET /creator/products → 新增或详情
→ 选择本人有效商业授权 + 一件 RIGHTS_CONFIRMED 作品
→ 上传封面/详情/可选附件，填写 SKU、销售范围、履约和售后
→ POST /creator/products（Idempotency-Key）
→ 同步文本与图片审核 → 版权初审 → 合规复核 → PUBLISHED
```

- 创建时前端只提交 `authorizationId`、`workId`，不得提交 `ipId`；服务端从授权反查 IP，并校验作品、授权与创作者同属且授权未过期、允许商用。
- 必填封面、版权声明与至少一个 SKU。SKU 不提交 `skuCode`，后端生成 `SKU-{IP资产编号}-{关联作品编号}-{商品编号末6位}-{两位顺序号}`；售价必须大于 0，库存可以为 0。品牌、生产方、条码、税率，以及商品视频/说明书/质检报告/生产许可证等 `attachments[]` 均为可选。
- 文本及封面、详情、SKU 配图、图片类附件同步审核为 `PASS/REVIEW` 后返回 `PENDING_COPYRIGHT_REVIEW`；版权合规人员在 `GET /copyright/products/pending?reviewNode=COPYRIGHT_INITIAL` 获取初审待办，并以 `POST /copyright/product-versions/{productVersionId}/reviews` 携带新的 `Idempotency-Key` 提交 `PASS|RETURN|REJECT`。初审通过进入 `PENDING_COMPLIANCE_REVIEW`，同一角色再以 `reviewNode=COMPLIANCE_REVIEW` 复核；仅复核通过进入 `PUBLISHED`。
- `CHECK_REJECTED` 或 `CHECK_ERROR` 不进入人工待办。创作者修正后用 `PATCH /creator/products/{productId}` 和新的 `Idempotency-Key` 重新提交；退回、驳回和检测失败可覆盖当前未发布版本。已发布商品必须先 `POST /creator/products/{productId}/delist`，下架后再次 PATCH 会生成新版本，历史版本与后续订单快照不被覆盖。
- 页面状态以接口返回为准：审核中禁止编辑；`RETURNED` 显示审核意见和补充项；`DELISTED` 显示“创建新版本重提”；`PUBLISHED` 显示下架动作。审核人员不得在前端直接改商品内容或 SKU。
