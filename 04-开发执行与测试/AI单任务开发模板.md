# 星衍树版权二创平台一期 MVP AI 单任务开发模板

版本：v0.4  
用途：将一个已拆分的研发、联调、测试或缺陷修复任务交给 AI 编程助手执行。  
关联文档：[API功能清单与开发任务拆分.md](API功能清单与开发任务拆分.md)、[OpenAPI_v0.4.yaml](OpenAPI_v0.4.yaml)、[测试验收标准与测试用例.md](测试验收标准与测试用例.md)

## 1. 使用规则

1. 一次只下达一个任务编号或一个紧密关联的小任务组；不要把“开发整个模块”交给单次 AI 任务。
2. 将模板中的 `[方括号]` 替换为明确内容后再发送；没有指定的内容不得由 AI 擅自猜测为新需求。
3. AI 可以阅读关联文档和现有代码，但只修改完成该任务所必需的文件。
4. AI 发现需求冲突、状态无法确定、接口字段缺失、外部服务规则未定时，应停止实现并列出问题；一般性的校验、错误处理和审计规则则按已有文档及常规实现完成，不重复询问。
5. 每项任务完成必须提交变更清单、测试结果和未完成事项；没有测试或无法运行测试必须说明原因。

## 2. 所有任务共用约束

将以下内容附在每份单任务指令末尾：

```text
通用约束：
1. 一期范围以《一期MVP需求基线与范围说明.md》为最高依据；发生冲突时停止并说明。
2. 数据库不建立物理外键；所有逻辑关系、数据范围、状态前置和并发控制在 Go 服务事务中实现。
3. 金额使用十进制字符串/高精度金额类型；业务 ID 使用字符串，不得用浮点数或 JavaScript Number 承载金额和大 ID。
4. 所有写接口实现权限、数据范围、状态机、乐观锁、幂等、审计日志；请求文本按规则调用第三方敏感内容检测。
5. 商品经系统自动校验、版权初审、合规复核后发布；活动只有系统自动校验与自动发布，不得实现活动人工发布审核；作品按版权/合规审核流程处理。
6. 授权支付成功后不得取消或退款；生产环境接入微信支付 V3，数字人民币作为后续渠道预留；一期不实现自动续期、发票、活动改期、商品草稿、多账号、优惠券或投诉工单。
7. 不得伪造存证成功。无真实服务商回执时只能为失败/处理中，并保留可重试记录。
8. 不得修改未被任务要求的业务规则、数据库历史数据或其他开发人员的代码；发现现有变更时先兼容并说明。
```

## 3. 后端接口开发模板

```text
请完成后端任务 [任务编号]：[任务名称]。

任务范围：
- 实现接口：[HTTP 方法 + 路径列表]。
- 主要角色与数据范围：[角色、组织范围、对象归属]。
- 涉及业务对象/数据表：[主写表、关联校验表、异步或联动表]。
- 前置状态与目标状态：[状态机规则]。

先阅读：
1. 《API功能清单与开发任务拆分.md》中的 [任务编号]；
2. 《OpenAPI_v0.4.yaml》中上述接口及共享模型；
3. 《业务状态机与流转规则.md》中 [对象名称]；
4. 《数据库设计说明.md》、数据库字段字典和 SQL 中涉及的数据表；
5. 《测试验收标准与测试用例.md》中的 [用例编号列表]。

实现要求：
- 请求/响应、错误码、鉴权方式与 OpenAPI 一致；字段无法支撑时不要私自加业务规则，提出问题。
- 写操作使用事务；校验对象存在、归属、数据范围、版本号与合法状态流转。
- 要求幂等的接口必须支持 Idempotency-Key，重复调用不重复扣减、生成合同、退款、分账或写状态历史。
- 对异步检测、支付、存证、回调等失败设计状态、重试/补偿入口和审计，不把“已提交”当作“已成功”。
- 补齐单元测试和接口测试，至少覆盖：成功、字段错误、未登录/越权、状态冲突、并发或重复提交。

完成后输出：
1. 实现摘要；
2. 变更文件及每个文件的用途；
3. 已实现接口及请求/响应示例；
4. 测试命令与结果；
5. 未解决问题、外部配置项或后续联调依赖。

[粘贴“所有任务共用约束”]
```

## 4. 前端页面开发模板

```text
请完成前端任务 [任务编号]：[页面/组件名称]。

任务范围：
- 所属端：[统一管理后台 Vue / 消费者 H5 Vue]。
- 页面路由：[路由]；可见角色：[角色]。
- 页面动作：[查询、创建、提交、审核、支付、发货等]。
- 调用接口：[OpenAPI 路径及操作]。
- 字段与选项依据：《页面功能与字段清单.md》中的 [页面编号/章节]。

先阅读：
1. 《页面功能与字段清单.md》中对应页面、字段和枚举；
2. 《OpenAPI_v0.4.yaml》中调用接口的请求、响应、错误码和鉴权；
3. 《业务状态机与流转规则.md》中对象状态与可执行动作；
4. 对应原型页面和现有项目组件规范；
5. 《测试验收标准与测试用例.md》中的 [用例编号列表]。

实现要求：
- 复用现有 Vue、路由、请求封装、组件、图标和样式规范；不引入无关框架或全局重构。
- 下拉、单选、复选和状态文字来自字典/API；不在页面写死业务状态判断。
- 操作按钮以接口返回的 availableActions、权限和页面状态为准；提交时传递 Idempotency-Key 与版本号（适用时）。
- 所有加载、空数据、无权限、字段校验、接口失败、处理中、成功和状态冲突都有明确反馈。
- 金额以字符串展示/提交；ID 不转换为 Number；私有文件只使用 fileId 和后端签发的短期下载地址。
- 商品页面按权限展示版权初审、合规复核动作；活动页面不出现人工发布审核动作；不得创建一期外功能入口。
- 完成页面级交互测试；必要时提供关键流程截图。

完成后输出：
1. 页面/组件、路由和接口绑定说明；
2. 变更文件清单；
3. 已验证交互和测试结果；
4. 需要后端、原型或产品补充的事项。

[粘贴“所有任务共用约束”]
```

## 5. 前后端联调模板

```text
请完成联调任务 [任务编号]：[业务链路名称]。

联调范围：[页面列表] → [接口列表] → [关键状态结果]。
测试角色：[角色账号]；前置数据：[IP/方案/授权/商品/活动等]。

请按《测试验收标准与测试用例.md》的 [用例编号] 执行，并逐项核对：
1. 前端请求字段、枚举、金额、ID、幂等键和版本号；
2. 后端响应、错误码、权限、状态、availableActions；
3. 数据库对象、状态历史、审计日志、异步检测/存证/分账记录；
4. 前端成功、失败、处理中和重试提示。

输出联调记录：每一步的页面操作、接口 requestId、关键响应、状态变化、发现的问题与建议责任方。不得通过手工修改数据库绕过链路。

[粘贴“所有任务共用约束”]
```

## 6. 测试执行模板

```text
请执行测试用例 [用例编号列表]，不修改业务代码。

先读取《测试验收标准与测试用例.md》、关联状态机与 OpenAPI。使用规定测试角色和测试数据，完整执行每个前置条件与步骤。

每个用例输出：
- 用例编号、执行环境、账号角色、前置数据；
- 实际步骤与接口 requestId；
- 实际结果、关键数据/日志检查结果；
- 通过/失败；失败则给出 P0-P3 级别、复现步骤、预期/实际差异和证据路径。

不得因用例失败而修改数据或放宽断言；需要修复时单独创建缺陷修复任务。
```

## 7. 缺陷修复模板

```text
请修复缺陷 [缺陷编号]：[缺陷标题]。

缺陷等级：[P0/P1/P2/P3]。
复现前置与步骤：[内容]。
预期结果：[内容]。
实际结果：[内容]。
证据：[截图/日志/requestId/接口响应]。

先定位根因，阅读相关业务状态机、OpenAPI、数据库设计和原测试用例。修复应最小化，不得用前端隐藏、吞错、手工改数据或放宽权限掩盖问题。

必须补充或修正自动化测试，覆盖原始复现、相邻状态、权限和幂等影响。输出根因、修改文件、回归范围、测试结果和残余风险。

[粘贴“所有任务共用约束”]
```

## 8. 任务完成回报格式

所有 AI 任务完成时，使用以下格式回报：

```markdown
## 任务结果

- 任务：`[任务编号] [任务名称]`
- 状态：`完成 / 部分完成 / 阻塞`
- 实现内容：
- 变更文件：
- 已实现接口或页面：
- 测试：`命令或步骤`，`结果`
- 关联用例：
- 未解决项与阻塞原因：
- 需要人工确认的业务问题：`无 / 问题列表`
```

## 9. 推荐下发顺序

1. 后端先按 `API-FND-01` 至 `API-FND-05` 完成会话、权限、审计、文件与外部适配基础；
2. 再按 `API-IP-*`、`API-AUT-*`、`API-CNT-*` 完成 IP、授权与创作主链路；
3. 前端按页面与接口依赖并行开发，联调时不等待全部页面完成；
4. 随后执行消费者交易、履约、售后、财务、存证任务；
5. 每完成一张任务卡即执行对应测试用例，最后执行完整主链路回归。
